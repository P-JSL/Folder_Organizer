# Folder Organizer

Windows에서 **내 컴퓨터의 폴더**를 선택해 파일을 살펴보고, 변경 내역을 미리 확인한 후 안전하게 정리하는 데스크톱 앱입니다. 파일은 외부 서버에 업로드하지 않습니다.

**v0.6.1은 Python판과 Rust판을 각각 정식 Windows ZIP으로 제공합니다.** 기존에 통과한 Python 구현과 Rust 수정본의 기능을 유지하고, 두 판의 버전과 릴리즈 정보를 0.6.1로 맞췄습니다. 정식 1.0.0으로 표시하기 전에 충족할 기준은 [조사·완료 기준](docs/V1_READINESS.md), 두 판의 구성과 지원 경계는 [Python·Rust 안내](docs/EDITIONS_0.6.0.md), 통합한 메뉴는 [기능 정리 결정](docs/FEATURE_DECISIONS.md)에 정리했습니다. 사용자 지시에 따라 이번 릴리즈에서 기존 검사와 앱 실행 검사를 반복하지 않습니다.

현재 안정판은 **v0.6.1**입니다. 중복 검사 결과를 재사용하는 즉시 정리, `delete_files` 보관, 복원 데이터 압축과 큰 목록의 조회·분석 개선을 포함합니다. 각 판의 자동 업데이트는 자기 판의 패키지만 확인합니다.

## Windows에서 사용

1. [Python판 Windows ZIP](https://github.com/P-JSL/Folder_Organizer/releases/latest/download/FolderOrganizer-Windows-x64.zip) 또는 [Rust판 Windows ZIP](https://github.com/P-JSL/Folder_Organizer/releases/latest/download/FolderOrganizer-Rust-Windows-x64.zip)을 다운로드합니다. 버전별 변경 사항과 체크섬은 [Releases](https://github.com/P-JSL/Folder_Organizer/releases)에서 확인할 수 있습니다.
2. ZIP 전체를 압축 해제한 뒤 Python은 `FolderOrganizer/FolderOrganizer.exe`, Rust는 `FolderOrganizerRust/FolderOrganizerRust.exe`를 실행합니다. 각 ZIP의 도우미·라이선스 파일과 Python의 `_internal` 폴더도 함께 보관해야 합니다.
3. **폴더 선택 → 분석**으로 시작합니다. 우선 작은 테스트 폴더에서 미리보기와 되돌리기를 확인하세요.

Windows 배포판은 Windows 10/11 x64를 대상으로 하며 **Python 설치가 필요 없습니다**. 소스 실행에는 Python 3.11 이상이 필요합니다. 실행 파일은 코드 서명되지 않아 Windows에서 게시자 확인 알림을 표시할 수 있습니다. Windows·Linux CI에서 검증하며 실행 파일은 Windows 러너에서 빌드합니다. macOS는 소스 실행 구조를 갖추었지만 별도 패키지나 실기기 검증을 제공하지 않습니다.

| 필요한 일 | 추가·개선한 기능 | 사용자가 확인할 점 |
| --- | --- | --- |
| 용량을 많이 쓰는 위치 찾기 | 종류·상위 폴더별 용량과 큰 파일·빈 파일 요약 | 요약은 논리적 파일 크기이며, 여는 것만으로 정리하지 않습니다. |
| 검토할 파일 빨리 좁히기 | 100 MiB 이상·0 B·수정 후 1년 필터, 최근 폴더 | 화면 필터는 검사 범위를 바꾸지 않으며 최근 폴더는 새로 분석합니다. |
| 큰 목록에서 유사 후보 찾기 | 자동·빠른 후보·전체 쌍 검색, 결과 범위 안내 | 빠른 후보는 일부 쌍을 놓칠 수 있습니다. 완전 중복 판정과 구분합니다. |
| 목록과 결과를 덜 기다리기 | 순차 탐색, 진행 이벤트 제한, 검색·정렬 키 준비, 검증 결과의 안전한 재사용 | 파일 내용이 바뀌면 기존 검증을 그대로 쓰지 않습니다. |
| 삭제한 파일 위치 알기 | 이 버전은 `delete_files` 한 곳으로 이동 | Windows·NAS 휴지통 이동이 보장된다는 뜻이 아닙니다. 기록과 함께 복원합니다. |
| 복원 데이터 용량 줄이기 | 압축 복원 정보와 별도 원본 보관 데이터 최적화 | 보관 바이트를 유지하며, 압축 이득이 없거나 실패하면 기존 파일을 남깁니다. |

v0.5.0의 새 삭제 작업은 `.folder-organizer/quarantine`과 `.folder-organizer/retained`를 추가로 만들지 않고, 현재 선택한 폴더의 `delete_files`로 이동합니다. 이 빌드에는 Windows·NAS 휴지통으로의 안전한 이동을 보장하는 실행 경로가 없어 `delete_files`를 사용합니다. NAS의 `#recycle` 폴더가 보인다는 것만으로 서버 휴지통 설정이나 파일별 복구 가능성을 보장하지 않습니다. `delete_files`, NAS의 `#recycle`·`@Recycle`, Windows의 `$Recycle.Bin`은 일반 분석 대상에서 제외합니다. 이전 버전이 만든 보관 폴더와 작업 기록은 계속 복원할 수 있도록 유지합니다.

생성일은 운영체제가 제공하는 실제 생성 시각만 표시합니다. Windows는 생성 시각을, 지원되는 macOS는 birthtime을 사용하며, Linux 등에서 제공되지 않으면 `제공되지 않음`으로 표시합니다. 메타데이터 변경 시각을 생성일로 표시하지 않습니다. 용량은 논리적 파일 크기이며 디스크 실제 할당량이나 중복 제거 후 확보 공간과 다를 수 있습니다.

`.exe`, `.msi`, `.dmg`, `.pkg`, `.deb`, `.rpm`, `.appimage`, `.desktop` 등은 응용 프로그램 관련 파일로 분류합니다. 선택한 폴더 내 파일을 관리하며, Windows 설치 프로그램 목록이나 레지스트리를 읽거나 프로그램을 제거하지 않습니다. 서로 다른 버전의 실행 파일은 이름이 유사해도 대체 가능한 프로그램으로 간주하지 않습니다. macOS `.app`은 내부 파일 단위로 표시하며, 앱 묶음을 손상시킬 수 있는 내부 파일 개별 이동은 차단합니다.

## 중복과 유사, 어떻게 다른가요?

| 판정 | 예시 | 앱이 확인하는 것 | 정리 방법 |
| --- | --- | --- | --- |
| 완전 중복 | 이름과 저장 위치는 달라도 모든 바이트가 같은 복사본 | 크기 → SHA-256 → 실제 바이트 비교 | 보존 규칙과 미리보기로 정리하거나, 첫 파일·보호 파일을 남기는 전용 버튼으로 즉시 실행 |
| 텍스트 유사 | 문서 초안과 수정본, 공백이 다른 텍스트 | 지원 UTF-8 파일의 어구 겹침과 길이 | 나란히 차이를 읽고 직접 선택 |
| 이미지 유사 | 크기·압축·형식이 다른 사진 | 축소된 구조·색·투명도·종횡비, EXIF 방향 보정 | 해상도·파일 정보·미리보기를 함께 검토 |
| 이름 유사 | 같은 제목의 다른 파일, 프로그램 설치 파일의 다른 버전 | 정규화된 이름의 글자 배열 | 약한 근거로 표시. 내용·앱 기능이 같다고 판단하지 않음 |

**유사도 100%는 완전 중복이나 삭제해도 된다는 뜻이 아닙니다.** 이름 점수가 높아도 텍스트·이미지의 다른 근거를 숨기지 않습니다. 실제 바이트를 읽어 확인할 수 없으면 '다름'으로 단정하지 않고 확인되지 않은 상태로 표시합니다. 자세한 예제와 한계는 [판정 안내](docs/DUPLICATES_AND_SIMILARITY.md), 유료 제품의 실제 조사 근거는 [상용 프로그램 비교](docs/COMPETITIVE_ANALYSIS.md)를 참고하세요.

## 반복해서 사용하는 작업 흐름

1. **검사 → 검사 범위 · 보존 설정**에서 비교 프리셋·기준값·제외 패턴·파일 크기 범위를 고릅니다. 범위나 재귀·숨김 옵션을 바꾸면 다시 분석해야 합니다. 목록의 검색·종류 필터는 화면 표시만 바꾸며 검사 범위를 바꾸지 않습니다.
   용량을 어디부터 줄일지 모르겠다면 **검사 → 용량·정리 요약**에서 큰 파일과 종류·폴더별 비중을 먼저 확인하세요. **대용량·빈 파일·오래된 파일** 필터는 검토할 파일을 보여주는 기능이며 자동 삭제하지 않습니다.
2. **검사 → 중복 검사**로 완전히 같은 파일을 찾습니다. 보존할 기준과 보호 폴더를 정하고 **보존 규칙으로 선택**합니다. 보호 폴더는 자동 선택에서 보존하며, 파일이 바뀌었거나 그룹이 겹치면 해당 그룹을 건너뜁니다. 직접 체크한 파일까지 변경 불가로 만드는 접근 제어 기능은 아닙니다.
3. **검사 → 유사 비교**는 사진·문서·이름 등 선택한 근거로 검토 후보를 찾습니다. 이름만 유사한 결과와 내용 근거가 있는 결과를 따로 볼 수 있습니다. **두 파일 나란히 비교**에서 원본 차이를 확인합니다. 유사 후보에는 보존 규칙을 자동 적용하지 않습니다.
4. 직접 정리할 파일을 체크하고 아래의 정리 방식과 **작업 미리보기**에서 전체 원본/대상 경로를 확인합니다. **정리 → 선택 항목을 중복으로 간주**는 중복이 검증되지 않았다는 안내를 거칩니다. 같은 제목의 문서에 겹치는 내용이 있으면 지원 파일을 두 개 이상 체크하고 **정리 → 체크한 파일 내용 병합**을 사용합니다.
5. **기록 → 작업 기록 · 복원**에서 변경을 되돌리고 **실행 로그**에서 파일별 처리 결과를 찾습니다. **도구**에서 손상 검사·복구본 만들기, **파일 → 내보내기**에서 목록이나 JSON/HTML 분석 보고서를 저장합니다. 개인 파일 내용이나 이미지 미리보기는 분석 보고서에 포함하지 않습니다.

이름의 기본 기준은 0.82, 텍스트·이미지는 각각 0.90입니다. 설정한 개별 기준값을 그대로 사용하며 점수는 통계적 동일 확률이 아닙니다. 유사 비교의 **자동** 방식은 작은 목록에서는 전체 쌍을, 큰 목록에서는 전체 파일을 살펴 뽑은 빠른 후보를 비교합니다. **빠른 후보**는 일부 유사 파일을 놓칠 수 있으며, 결과가 없다고 비슷한 파일이 없다는 뜻은 아닙니다. **전체 쌍**도 기본 25,000쌍 한도에 닿으면 미검사 범위를 알립니다. 먼저 수행하는 완전 중복 검사는 유사 쌍 한도의 대상이 아닙니다. 한도 도달·읽기 실패·지원 범위를 결과와 보고서에 표시합니다. UTF-8 텍스트는 최대 256KiB·앞 4,096단어, 이미지는 최대 40MP이며 여러 프레임의 전체 움직임·문서 의미·임의 회전/크롭을 인식하지 않습니다.

## 조회·분석 속도와 검사 범위

파일을 한 번씩 방문하는 목록 탐색과 용량 요약은 파일·폴더 수에 비례하도록 구성했습니다. 화면 정렬은 별도이며 `O(n log n)` 비용이 들 수 있습니다. 실제 내용을 확인하는 중복 검사는 읽어야 할 파일 바이트에도 시간이 걸리므로 모든 파일에 대해 `O(n)`보다 빠른 처리를 보장하지 않습니다.

큰 목록의 빠른 유사 비교는 파일마다 제한된 후보를 찾습니다. 작은 목록의 전체 비교보다 범위를 넓게 살필 수 있지만 모든 조합을 확인하는 방식은 아닙니다. 같은 크기·해시·실제 바이트를 검증하는 **완전 중복 기준은 유지**합니다. 재현 가능한 측정 방법과 각 처리 단계의 한계는 [성능·복잡도 안내](docs/PERFORMANCE.md)를 참고하세요.

## 압축 메타데이터로 작업 복원하기

복원용 메타데이터는 **원래 경로·보관 위치·파일 해시·작업 결과를 담은 설명서**입니다. 조건에 맞는 작업이 완료되면 인증된 압축 메타데이터를 추가로 저장하고, 복원할 때 현재 기록과 맞는지 확인해 사용합니다. 압축 이득이 작거나 시간이 오래 걸리면 기존 작업 기록으로 진행합니다. 압축 기록이 손상된 경우에도 유효한 기존 기록이 있으면 그 기록으로 전환하고 안내합니다.

**메타데이터만으로 파일 내용을 다시 만들 수는 없습니다.** 실제 복원에는 `delete_files`의 원본 또는 기존 보호 사본·검증된 압축 보관 바이트가 필요합니다. 따라서 `delete_files`와 `.folder-organizer`의 기록·인증 정보·보관 데이터를 함께 유지하세요. 압축 메타데이터를 추가해도 손실된 내용을 추측해 복구하지 않습니다. 손상 파일에서 읽을 수 있는 내용을 새 파일로 보존하는 기존 복구 기능도 유지합니다.

실제 보관 파일이 커지면 **기록 → 작업 기록 · 복원 → 복원 데이터 용량 최적화**를 별도로 요청할 수 있습니다. 고정 크기 청크의 SHA-256이 같으면 보관 데이터를 공유하고, 각 청크는 빠른 압축과 원시 저장 중 더 작은 쪽을 선택합니다. 원본 전체의 해시로 다시 확인한 뒤 복원에 필요한 독립적인 데이터를 남깁니다. 살아 있는 다른 원본 파일이 나중에 삭제되어도 그 파일에 의존해 복원하는 방식은 아닙니다. 이미 압축된 데이터나 고유한 데이터는 효과가 작을 수 있으며 전역 최소 용량을 보장하지 않습니다.

규칙 작성 순서와 이중 보호 절차는 [자동 분류 가이드](docs/AUTOMATIC_CLASSIFICATION.md)를 참고하세요. **첫 번째 제외 삭제**의 '첫 번째'는 중복 검사 그룹에 표시된 첫 파일입니다. 최신 파일이나 가장 좋은 원본을 뜻하지 않습니다. 자동 선택에서 보호 폴더는 보존합니다. 안전 보관은 작업 기록에서 복원할 수 있으며 공간을 즉시 확보하지 않습니다.

## 처음 설치한 뒤 확인할 순서

1. Windows ZIP을 새 폴더에 모두 풀고, 테스트용 파일 복사본이 있는 폴더를 선택합니다.
2. 용량 요약과 대용량·빈 파일·오래된 파일 필터를 확인합니다. 목록 표시만 바뀌고 파일은 이동되지 않아야 합니다.
3. 같은 내용의 파일 세 개로 중복 검사를 실행합니다. 그룹의 첫 파일과 보호 대상을 확인한 뒤 **첫 번째 파일만 남기고 나머지 삭제**를 누릅니다. 이 전용 버튼은 추가 미리보기·확인·전체 재검사 없이 나머지를 `delete_files`로 이동합니다.
4. 남긴 파일은 원래 위치에, 처리한 파일은 `delete_files`에 있는지 확인하고 **작업 기록 · 복원**에서 되돌려 보세요. 같은 이름의 다른 파일이 생기면 덮어쓰지 않아야 합니다.
5. 복원 데이터 용량 최적화를 사용할 경우 미리보기·절감 결과·기존 파일 유지 또는 압축 보관 상태를 확인하고 다시 복원해 원본 내용이 같은지 확인합니다.
6. NAS에서 시험할 때는 서버의 휴지통 폴더가 보이는지와 앱의 실제 삭제 대상 위치를 구분해 확인합니다. 이 버전은 `delete_files`를 사용하며 서버 설정을 바꾸지 않습니다.

전체 변경 표와 확인 항목은 [v0.5.0 사용 확인 안내](docs/BUILD_REVIEW_0.5.0.md)에서도 볼 수 있습니다.

## 겹치는 내용을 병합하기

![겹치는 문단과 유지할 내용을 확인하는 실제 병합 미리보기](docs/merge.png)

이름이 같거나 비슷해도 내용이 서로 다를 수 있습니다. 병합은 사용자가 체크한 **2~20개 파일**을 대상으로 미리보기를 만든 뒤 실행하며, 제목 유사도만으로 자동 실행하지 않습니다. 파일당 8 MiB, 전체 32 MiB, 전체 문단·행 200,000개까지 지원합니다. 표는 최대 1,000열·전체 1,000,000셀로 제한합니다.

- UTF-8 또는 UTF-8 BOM의 `.txt`·`.md`: 줄바꿈을 정규화하고 **완전히 같은 문단**을 한 번씩 남깁니다. 서로 다른 문단과 처음 나타난 순서를 보존합니다.
- `.csv`·`.tsv`: 같은 형식과 동일한 열 제목·순서·열 수를 가진 파일에서 **모든 셀 값이 같은 행**을 한 번씩 남깁니다. CSV와 TSV를 서로 섞지 않습니다.
- 기본 **새 병합본만 만들기**는 원본을 유지합니다. **병합 후 원본을 안전 보관으로 이동**을 선택하면 새 병합본의 검증 뒤 원본을 보관합니다. 이 보관 작업을 기록에서 복원해도 새 병합본은 남습니다.

병합본은 `_병합` 이름의 새 파일로 만들며 기존 파일을 덮어쓰지 않습니다. 미리보기의 제거 문단·행 수와 내용을 확인하세요. 서로 다른 문장의 의미나 충돌을 판단하거나, CSV 수식의 동작을 고치지 않습니다. 이미지·실행 파일·Office 문서 등은 내용 병합 대상이 아닙니다. 실행 중 파일이 바뀌거나 보관이 실패하면 부분 완료를 알리며 새 병합본과 보관·원본 상태를 결과에서 확인할 수 있습니다.

진행도·표본 검사·캐시와 재현 측정은 [분석 속도 안내](docs/PERFORMANCE.md), 로그 위치와 내보내기는 [로그 안내](docs/LOGGING.md)에 정리했습니다.

## 자동 업데이트

Windows ZIP 배포판에는 업데이트 기능이 기본 활성화되어 있습니다. 새 정식 버전을 GitHub Releases에서 확인하고 Windows ZIP과 체크섬을 내려받아 SHA-256 및 패키지 구조·버전을 검증합니다. 정리 작업 중에 앱을 강제 종료하지 않으며, 다운로드된 업데이트는 **앱을 정상 종료한 뒤** 별도 도우미가 적용하고 앱을 다시 실행합니다. 교체 실패 시 이전 앱 디렉터리로 되돌립니다. 설정에서 자동 확인을 끄거나 수동으로 확인할 수 있습니다.

인터넷 연결과 앱 폴더에 대한 쓰기 권한이 필요합니다. 관리자 권한이 필요한 Program Files 대신 사용자 쓰기 가능한 폴더에 압축을 푸세요. **도구 → 자동 업데이트**에서 자동 확인을 끄거나 **업데이트 확인**을 실행할 수 있습니다. 오프라인·GitHub API 제한·체크섬 오류·잠긴 파일이 있으면 기존 버전을 유지하고 오류를 표시합니다. 소스 실행과 Linux/macOS에서는 자동 교체를 하지 않습니다. 앱이 실행되지 않는 동안에는 업데이트를 확인하지 않으며, 다른 사람의 PC에 직접 접속해 업데이트하는 서비스가 아닙니다.

업데이트 확인은 GitHub에 버전 메타데이터와 배포 파일을 요청합니다. 개인 파일·선택 폴더 경로는 전송하지 않습니다. HTTPS와 릴리스 체크섬을 검증하며, 별도의 코드 서명 인증서는 포함하지 않습니다. 개발자는 버전을 올리고 `vX.Y.Z` 태그를 게시해야 합니다. 같은 태그의 파일을 덮어쓰는 방식으로는 새 버전을 배포하지 않습니다.

## 데이터 보호와 복구 범위

- 수동 정리·자동 분류·병합은 미리보기와 명시적 확인 후 실행합니다. **첫 번째 파일만 남기고 나머지 삭제**는 현재 검증된 중복 결과에서 즉시 실행하는 전용 동작입니다. 유사도 결과는 자동 삭제 근거가 아닙니다.
- `.folder-organizer`는 작업 기록·인증 정보·압축 보관 데이터와 기존 버전의 보호 사본을 보관하는 전용 폴더입니다. 새 삭제·복원은 `delete_files`의 파일을 직접 이동하며 `quarantine`·`retained`를 추가로 만들지 않습니다. 복원하려면 `delete_files`와 `.folder-organizer`를 원래 폴더와 함께 유지하세요. 일반 복사·이동의 보호 사본과 기존 보관 데이터도 임의로 지우지 마세요. 안전 보관은 디스크 공간을 즉시 회수하지 않으며 별도 데이터 최적화에도 추가 여유 공간이 필요할 수 있습니다. 다른 드라이브로 복사하거나 오류가 발생한 경우 대상 폴더 쪽에도 `.folder-organizer`가 생성될 수 있으므로 작업 결과에 표시된 보관 경로를 함께 유지하세요.
- 원본과 대상의 내용·변경 여부를 확인하며, 기존 파일을 덮어쓰지 않습니다. 원래 경로에 새 파일이 생기거나 정리 후 파일을 편집하면 되돌리기가 충돌을 보고하고 파일을 보존합니다.
- 복사 작업도 기록에서 되돌릴 수 있습니다. 파일 내용이 바뀌지 않았고 이 앱이 생성한 복사본임을 확인한 경우에만 대상 위치에서 보호 보관으로 옮깁니다. 변경된 파일은 충돌을 보고하고 보존합니다.
- 심볼릭 링크를 따라가지 않습니다. 관리 권한 상승을 요구하지 않습니다. 시스템 폴더·프로그램 설치 폴더 대신 문서·다운로드 등 개인 데이터 폴더에 사용하세요.
- 대용량 파일은 스트리밍 해시를 사용하며, 이미지·텍스트·유사 후보 수·압축 해제 크기는 제한합니다. 일부 파일을 건너뛴 경우 진행 상태와 경고를 확인하세요. 취소된 분석은 전체 결과가 아닙니다.
- ZIP 복구는 읽을 수 있는 항목을 새 ZIP에 보존합니다. 손실된 항목은 재생성하지 못하며, 일부 항목만 복구되면 `partial`로 표시합니다. DOCX/XLSX/PPTX는 내부 구조가 손실되면 앱에서 정상적으로 열리지 않을 수 있습니다.
- 이미지 복구는 디코딩 가능한 데이터를 다시 저장하는 방식, PDF 복구는 읽을 수 있는 구조를 다시 쓰는 방식입니다. 손실된 원본 바이트, 암호, 임의 실행 파일/동영상 손상, 디스크에서 영구 삭제된 파일을 복원하지 못합니다. 디스크 복구 도구를 대체하지 않습니다.
- 정리 작업의 복원과 손상 파일 복구는 별개입니다. 중요한 데이터는 별도 장치에 백업하세요. 앱을 처음 사용하는 동안에는 원본 복사본으로 검증하는 것을 권장합니다.

## 소스에서 실행

Windows PowerShell:

```powershell
git clone https://github.com/P-JSL/Folder_Organizer.git
cd Folder_Organizer
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m folder_organizer
```

Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m folder_organizer
```

GUI는 로컬 데스크톱 세션에서 실행해야 개인 컴퓨터의 폴더를 선택할 수 있습니다. 클라우드 실행에서 개인 컴퓨터의 드라이브에 접근하지 않습니다. Ubuntu/Debian은 기본 Qt 라이브러리로 `libegl1`, `libopengl0`가 필요하며, 데스크톱의 xcb 플러그인 오류에는 배포판의 Qt/X11 런타임도 설치하세요. 자동 테스트는 `QT_QPA_PLATFORM=offscreen`을 사용합니다.

읽기 전용 분석:

```sh
python -m folder_organizer --cli /path/to/folder --duplicates --similar
folder-organizer-cli /path/to/folder --csv new-inventory.csv
folder-organizer-cli /path/to/folder --duplicates --json new-analysis.json
folder-organizer-cli /path/to/folder --similar --similar-method text --text-threshold 0.9 --exclude 'Backup' --exclude '*.tmp' --html review.html
```

CLI는 파일을 정리하지 않습니다. `--min-size`/`--max-size`는 바이트 단위이며 `--exclude`는 여러 번 지정할 수 있습니다. 보고서와 CSV는 이미 존재하는 파일을 덮어쓰지 않습니다. HTML은 읽기 편하도록 최대 1,000그룹·2,000파일을 표시하고, JSON은 전체 결과와 근거를 보관합니다.

## 테스트·배포

```sh
python -m pytest -q
python -m build
python -m pip install -e '.[bundle]'
python -m PyInstaller --noconfirm --clean --onedir --windowed --name FolderOrganizer --collect-data PySide6 desktop_entry.py
```

GUI 없는 환경에서는 테스트 앞에 `QT_QPA_PLATFORM=offscreen`을 설정하세요. Windows 실행 파일은 Windows에서 빌드해야 합니다. `v*` 태그를 push하면 `.github/workflows/release.yml`이 Windows 테스트, 실행 파일 패키징, 실제 실행 파일의 분석·내보내기·업데이트 도우미 교체 검증, ZIP·SHA-256 체크섬을 포함한 GitHub Release 게시를 수행합니다. 이 워크플로가 성공하기 전에는 Windows 배포가 완료된 것으로 간주하지 않습니다.
