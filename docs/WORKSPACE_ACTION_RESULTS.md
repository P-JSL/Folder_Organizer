# 단일·다중 폴더 작업 공간 개선 확인 결과

2026-11-03(KST) 기준입니다. **최신 공개 릴리즈는 v0.7.0**이며 이번 개선을 새 릴리즈로 게시하지 않았습니다. v0.9.0의 원래 Python·Rust ZIP·체크섬·배포 기록은 [DOWNLOADS/v0.9.0](../DOWNLOADS/v0.9.0/README.md)에 보관했습니다. 이전 태그와 ZIP을 새 소스로 교체하지 않았습니다.

## 구현한 범위

- Python·Rust 모두 폴더 한 개 또는 여러 개를 같은 메인 화면에서 분석하고, 완전 중복·유사 검사와 복사·이동·삭제 보관·규칙 분류·내용 병합을 연결했습니다.
- 상단 리본 도구 모음, 왼쪽 검색 폴더·필터, 가운데 체크 가능한 결과, 오른쪽 파일 정보, 아래 종류별 요약으로 구성했습니다. 진행·취소와 실제 폴더별 기록·복원도 연결했습니다.
- 통합 중복 그룹 전체의 첫 파일·보호 대상을 남기고 실제 소속 폴더별 `delete_files`로 이동합니다. 현재 검증 근거를 재사용하며 추가 전체 탐색·해시·확인 창을 실행하지 않습니다.
- 실제 원본·보존 폴더별 잠금, 전체 계획의 원본·대상·보존 파일 충돌 확인, 출력 이름의 공통 예약과 서명된 계획을 사용합니다. 중첩 경로는 실제 소속에 한 번만 연결하며 가상 공통 원본 폴더를 만들지 않습니다.
- 작업·복원·복구·병합 후 기존 작업 권한과 완료 표시를 무효화합니다. 내보낸 JSON은 계속 `action_authority=false`이며 현재 프로세스의 분석 세션을 대신할 수 없습니다.

## 새 사례만 확인

앱 변경 소스는 [`899171286e9d12291568d742afe4866ca7555d0f`](https://github.com/P-JSL/Folder_Organizer/commit/899171286e9d12291568d742afe4866ca7555d0f)입니다. 이후 Windows 확인 보완은 워크플로와 새 흐름 검사 파일만 변경했으며 앱 구현은 바뀌지 않았습니다.

첫 Windows 실행 [41525952508](https://github.com/P-JSL/Folder_Organizer/actions/runs/41525952508)은 Python 26건과 Rust 17건·GUI 컴파일이 통과했고 실제 Python 작업자 흐름 2건이 실패하여 **전체 실행 결과는 실패**였습니다. 그 뒤 통과한 43건을 다시 실행하지 않았습니다.

두 흐름의 실패 원인은 검사 코드의 `QTest.qWait` 대기였습니다. Windows 파일 시스템 호출이 GIL을 놓을 때 Qt 대기가 이를 점유해 작업자 진행을 늦췄습니다. 스레드 위치를 수집해 실제 작업이 진행 중임을 확인하고, GUI 이벤트 처리 뒤 Python `time.sleep`으로 실행 시간을 양보하도록 바꿨습니다. **15초 제한 시간과 원본·해시·재검사 금지 조건은 유지**했습니다. 금지 동작 감시도 작업자 오류로 기록되는 `AssertionError`를 사용하도록 보완했습니다.

최종 [41528577873](https://github.com/P-JSL/Folder_Organizer/actions/runs/41528577873), 소스 [`089c81f5655794f6fd93e86e73fa143ce981063e`](https://github.com/P-JSL/Folder_Organizer/commit/089c81f5655794f6fd93e86e73fa143ce981063e)에서 해당 2건만 **2.87초에 통과**했습니다. Rust 작업은 스킵했습니다. 진단용 재실행도 실패했던 두 항목에만 한정했습니다.

기존 전체 검사, v0.9.0 이전 검사, 기존 Windows 네이티브·CLI·화면 캡처 드라이버는 실행하지 않았습니다. 새 확인 워크플로는 수동 실행만 지원하며 모든 main 커밋에 `[skip ci]`를 유지했습니다. 화면 캡처·새 배포 ZIP 생성·릴리즈 게시는 진행하지 않았습니다.

이 결과는 임시 합성 자료와 Windows 러너의 로컬 파일 시스템 범위입니다. 물리 NAS·HDD·콜드 캐시·대량 파일 전체 성능이나 기존 모든 기능의 재검증을 뜻하지 않습니다. 사용법은 [통합 작업 공간 안내](WORKSPACE_ACTIONS.md)에 있습니다.
