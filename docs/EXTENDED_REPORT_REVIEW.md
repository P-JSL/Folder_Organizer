# v0.7.0 확장 기술보고서 대조 검토

검토 자료는 사용자가 제공한 `FolderOrganizer_v0.7.0_정밀기술검토_확장보고서.pdf` 23쪽입니다. 배포본을 설명하는 부분은 v0.7.0 태그 `664e574a772fda1a41b28e4bad577773c4862d1f`와 보존된 측정 자료를 기준으로 대조했습니다. 보고서에 적힌 구현 순서·수용 기준·재현 명령은 참고 자료이며 별도의 사용자 지시로 간주하지 않았습니다.

사용자가 이번 작업에 선택한 범위는 **기존 코드·알고리즘 개선과 여러 폴더 선택·읽기 전용 통합 분석**입니다. 자동 감시·예약 갱신은 선택한 범위에 포함되지 않습니다. 기존 단일 폴더 정리와 복원 기록의 계약을 유지하며, 다른 폴더의 결과를 기존 `keep-first` 변경 API에 직접 주입하지 않습니다.

## 이번에 보완한 증거 보존

`windows_python_bundle_v070.py`는 새 `PackageEvidence` 경로에서 진행 단계와 완료 여부를 콘솔 출력보다 먼저 보존합니다. 실제 실행 파일 SHA-256·실행 인자·종료 코드, CLI stdout/stderr·원본 보고서의 SHA-256, GUI 이미지의 파일 크기·SHA-256을 기록합니다. 명령이 아직 끝나지 않았으면 종료 코드는 `null`이며, 후속 검사 실패는 `failed`로 기록합니다.

JSON은 같은 디렉터리의 임시 파일에 쓰고 flush/fsync 후 원자 교체합니다. 교체가 실패하면 이전의 완전한 JSON이 남으며, 미완료 기록을 성공으로 덮어쓰지 않습니다. 성공 기록은 모든 패키지 확인이 끝난 뒤 저장하고 마지막 콘솔 출력은 ASCII JSON으로 전달합니다.

워크플로는 후속 검사·출력 실패에도 `always()`로 **실제로 생성된 파일만** 별도 원시 증거 아티팩트에 보존합니다. 이 아티팩트의 존재는 검사 성공을 의미하지 않으며 기존 게시 게이트를 우회하지 않습니다. 원본 CLI 보고서·출력·이미지가 보존돼야 나중에 제3자가 직접 확인할 수 있습니다.

새 증거 실패 경로 2건만 실행했습니다: GUI 이후 실패가 발생해도 이미지 해시·실패 단계·종료 코드를 보존하는 경우, JSON 교체 중단 시 이전 기록이 유효하게 남는 경우입니다. 기존 Windows 패키지/GUI/코덱 검사는 재실행하지 않았습니다. 실제 Windows 실행은 이 변경 작업에서 수행한 것으로 주장하지 않습니다.

## 성능 및 신규 분석의 해석 경계

이번 코드 개선의 검증 결과는 변경한 함수와 새 다중 폴더 입력에 한정합니다. 기존 v0.7.0의 4.37배·5.78배 수치는 새 코드의 성능이 아니며 새 기능의 속도 배수로 재사용할 수 없습니다. 캐시의 힌트와 파일 변경 작업에 필요한 인증된 증거도 구분합니다. 다중 폴더 결과의 `action_authority=false`는 파일을 이동·삭제할 수 있는 실행 계획이 아니라는 계약입니다.

기존 릴리즈 태그와 배포 ZIP은 이 작업의 코드 검토·증거 보존 개선과 구분합니다. 현재 작업을 새 Windows 빌드, 공인 서명, 실제 NAS 시험 또는 자동 감시의 완료로 표현하지 않습니다.

구현한 화면·CLI·새 스키마·최적화 계측과 새 검사 52건의 범위는 [여러 폴더 분석 안내](MULTIROOT_ANALYSIS.md)에 기록했습니다. Python과 Rust에서 4가지 새 다중 폴더 입력의 의미를 대조한 결과도 포함하며, 기존 배포본의 4~6배 수치를 이번 변경의 성능으로 재사용하지 않습니다.
