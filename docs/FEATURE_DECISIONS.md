# 1.0.0을 위한 기능 정리 결정

기준일: **2026-10-28**. 실제 사용 통계가 없으므로 특정 기능의 이용률이 낮다고 단정하지 않습니다. 제거 판단은 **같은 일을 하는 중복 진입점, 현재 지원 범위 밖의 기능, 비용에 비해 근거가 부족한 자동화**를 기준으로 합니다. 사용자가 직접 요청한 병합·수동 안전 보관·복원·로그·자동 업데이트는 유지합니다.

## 제거해도 보존해야 하는 것

UI에서 중복된 진입점을 줄여도 다음 계약은 제거하지 않습니다.

- 기존 작업 기록의 `date`, `extension`, `quarantine` 등 모드와 원래 경로를 해석하는 복원 호환 계층.
- `.folder-organizer`의 키·인증된 기록·압축 데이터·과거 보호 사본과 `delete_files`에 보관된 실제 파일.
- 저장된 규칙과 설정을 읽어 같은 의미를 유지하거나, 변환할 수 없는 항목을 명확히 알리는 처리.
- 작업 중 취소·파일 변경·권한·공간 부족·이름 충돌에 대한 원본 보존 동작.

“불필요한 기능 제거”를 이유로 기존 사용자의 보관 파일이나 기록을 일괄 삭제하지 않습니다. 원시 복구 데이터가 있는 폴더를 빈 UI처럼 보이게 만들기 위한 자동 정리도 하지 않습니다.

## 두 언어 버전의 구성

Python판은 기존 PySide6 사용자 경험과 성숙한 파일 작업·복원 경로를 개선합니다. Rust판은 **별도 Rust 구현과 배포 파일**로 만들며, Python 실행 파일을 호출하는 단순 포장판과 구분합니다. 공통 기능의 의미·파일 보호 조건·지원 한도는 같게 맞추고, 구현 또는 검증이 끝나지 않은 부분은 각 판의 지원 표에 표시합니다.

Rust 언어로 다시 썼다는 사실은 더 빠른 속도나 동일한 복원 형식의 증거가 아닙니다. 실제 비교는 같은 데이터·장치·캐시 조건과 같은 작업 범위에서 수행합니다. 1.0.0 준비 항목과 공식 조사 근거는 [V1_READINESS.md](V1_READINESS.md)에 있습니다.

## 검증 재사용 방침

기존에 통과한 동일 코드의 검사는 사용자 지시에 따라 스킵합니다. UI 진입점 통합·새 성능 알고리즘·Rust 코드처럼 이번에 바뀐 동작에 필요한 새 검증은 이전 기능 검사를 반복하는 것과 구분합니다. 검증하지 않은 부분은 “기존 검사 통과”로 대체하지 않고 지원 상태를 그대로 기록합니다.
