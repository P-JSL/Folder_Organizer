# 화면에서 기능 이해하기

이 문서는 **v0.5.0 정식 버전**의 기능과 사용 순서를 설명합니다. Windows 배포 파일과 체크섬은 저장소의 [Releases](https://github.com/P-JSL/Folder_Organizer/releases/tag/v0.5.0)에서 받을 수 있습니다.

아래 이미지는 개인 자료 대신 임시 예시 파일로 **실제 앱을 실행해 캡처한 화면**입니다. 설치된 사용자 설정과 원본 자료를 사용하지 않았습니다.

## 처음에는 폴더만 선택하세요

![처음 실행한 화면](welcome.png)

폴더를 선택하면 파일별 용량과 날짜를 살펴봅니다. 이 단계에서는 파일이 바뀌지 않습니다. 상단은 현재 상태에 맞춰 다음 작업을 안내합니다. 메인 화면의 버튼을 줄이고 전체 기능을 헤더의 드롭다운 메뉴로 모았습니다. **도움말 또는 F1**은 파일을 바꾸지 않는 설명 창입니다.

| 상단 메뉴 | 찾을 수 있는 기능 |
| --- | --- |
| 파일 | 폴더 선택·최근 폴더·다시 분석·목록 선택·위치 열기·목록/분석 보고서 내보내기 |
| 검사 | 용량·정리 요약·완전 중복 검사·유사 비교·검사 설정 |
| 정리 | 규칙 분류·중복 자동 정리·선택 파일 정리·내용 병합·중복으로 간주 |
| 기록 | 실행 로그·작업 기록과 복원·활동 및 진단 로그 |
| 보기 | 다크 모드(기본)·라이트 모드 |
| 도구 | 손상 검사·복구본 만들기·업데이트 확인과 자동 업데이트 설정 |
| 도움말 | 사용 안내·중복과 유사의 차이 |

화면 색은 **보기**에서 바꾸며 선택은 이 컴퓨터에 저장됩니다. 검사·정리 조건과 파일은 바뀌지 않습니다.

![정리 메뉴를 펼친 실제 헤더 드롭다운](menu.png)

정리 기능은 위 메뉴에서 찾을 수 있습니다. 실행 조건이 갖춰지지 않은 항목은 비활성화됩니다.

## 목적에 맞는 기능을 고르세요

| 다크 모드 · 기본 | 라이트 모드 |
| --- | --- |

두 화면은 같은 예시 파일을 다른 색으로 표시한 것입니다. **보기**에서 바꿀 수 있으며 검사 결과와 선택 항목은 그대로 유지됩니다.

| 하고 싶은 일 | 사용할 기능 | 실행 결과 |
| --- | --- | --- |
| 어디부터 정리할지 찾기 | 검사 → 용량·정리 요약 | 폴더·종류별 용량과 큰 파일·빈 파일을 살펴봅니다. 파일은 변경하지 않습니다. |
| 같은 내용을 여러 번 저장했는지 확인 | 검사 → 중복 검사 | 내용이 완전히 같은 파일을 그룹으로 보여줍니다. 검사만으로 변경하지 않습니다. |
| 비슷한 사진이나 문서 버전 비교 | 검사 → 유사 비교 | 직접 확인할 후보를 보여줍니다. 높은 점수는 완전 중복의 뜻이 아닙니다. |
| 종류·날짜·원하는 조건으로 폴더 나누기 | 정리 → 규칙 분류 | 규칙으로 분류안을 만들며 복사가 기본입니다. 분석한 전체 파일 중 조건에 맞는 항목을 사용합니다. |
| 직접 고른 파일을 복사·이동·보관 | 체크 → 아래 정리 방식 → 미리보기 | 파일 목록에서 체크한 항목만 수동 작업 대상으로 사용합니다. |
| 같은 문단·데이터 행을 한 번씩 모으기 | 두 개 이상 체크 → 정리 → 체크한 파일 내용 병합 | 원본을 남기고 새 병합본을 만듭니다. 원본 안전 보관은 별도로 선택합니다. |
| 이전 작업 되돌리기 | 기록 → 작업 기록 · 복원 | 변경되지 않고 충돌하지 않는 파일을 확인해 작업을 되돌립니다. |
| 파일별 실제 처리 결과 찾기 | 기록 → 실행 로그 | 실행 시작·파일별 결과·완료·실패를 검색합니다. 로그 화면은 파일을 복원하지 않습니다. |
| 앱 진행 상황이나 오류 진단 | 기록 → 활동 · 진단 로그 | 검사와 업데이트를 포함한 앱 활동을 설명합니다. |

행을 클릭해 강조하는 것과 **체크 상자를 선택하는 것**은 다릅니다. 체크한 파일은 검색으로 숨겨도 선택이 남습니다. 화면의 ‘숨겨진 파일 포함’ 안내와 미리보기의 전체 대상 목록을 확인하세요.

## 용량을 많이 쓰는 곳부터 확인하세요

**검사 → 용량·정리 요약**은 이미 분석한 파일 정보로 폴더·종류별 용량과 큰 파일을 모아 보여줍니다. 파일을 하나씩 열지 않고도 무엇을 살펴볼지 고를 수 있습니다. 빈 파일은 0바이트라는 의미이며 불필요한 파일이라고 확정하지 않습니다. 용량은 논리적 크기로, 디스크 실제 사용량이나 정리 후 확보량과 다를 수 있습니다.

목록에서 **대용량 (100 MiB 이상)**, **빈 파일 (0 B)**, **오래된 파일 (수정 후 1년)**을 골라 표시를 좁힐 수 있습니다. **전체 파일**로 돌아가면 조건을 해제합니다. 필터는 표시만 바꾸고 기존 체크를 유지합니다. 자동 분류와 검사는 전체 분석 범위를 사용하므로, 표시된 파일만 대상으로 하려면 체크와 미리보기의 전체 경로를 확인하세요. 검사할 범위 자체를 줄이려면 폴더나 검사 설정을 바꾸고 다시 분석합니다.

**파일 → 최근 폴더**는 이 컴퓨터에 최근 선택한 위치를 최대 10개 저장합니다. 위치를 고르면 현재 검사 설정으로 다시 분석합니다. 새 분석 결과를 기다린 뒤 파일을 확인하세요. 폴더가 이동되었거나 접근할 수 없으면 현재 위치를 다시 선택합니다.

## 유사 검색은 범위에 맞게 고르세요

검사 설정에서 유사 검색 방식을 고를 수 있습니다. 처음에는 **자동**을 사용하세요. 작은 범위에서는 전체 비교를 수행하고, 파일이 많아지면 제한된 후보를 찾는 방식으로 전환합니다.

| 검색 방식 | 이런 경우에 적합 | 확인할 점 |
| --- | --- | --- |
| 자동 | 평소 사진·문서 폴더 확인 | 결과에서 실제 사용한 방식과 제한 여부를 확인합니다. |
| 빠른 후보 검색 | 파일이 많아 우선 검토할 후보가 필요할 때 | 모든 파일 쌍을 비교하지 않아 유사 파일을 놓칠 수 있습니다. |
| 전체 쌍 비교 | 좁힌 폴더에서 더 빠짐없이 비교하고 싶을 때 | 비교할 쌍이 빠르게 늘어납니다. 최대 비교 한도·읽기 실패가 있으면 전체 검사를 마친 결과가 아닙니다. |

빠른 검색에서 후보가 없다는 결과는 ‘유사한 파일이 없다’는 증명이 아닙니다. 유사 후보의 점수도 완전 중복이나 삭제 가능 여부를 뜻하지 않습니다. 필요한 후보는 **두 파일 나란히 비교**에서 직접 확인하세요. 완전 중복 검사는 유사 검색 방식과 별개로 전체 SHA-256과 실제 바이트를 확인합니다.

파일 조회와 요약은 파일 정보를 한 번씩 처리하도록 개선했습니다. 화면 정렬에는 추가 작업이 필요하며, 내용 검사는 실제 바이트를 읽어야 합니다. 파일 수에 상관없이 일정한 시간이 걸리거나 모든 분석이 O(n) 이하라는 뜻은 아닙니다. 검증 방법과 측정 범위는 [성능 안내](PERFORMANCE.md)를 참고하세요.

## 중복 결과에서는 남길 파일을 정하세요

![중복 결과 화면](comparison.png)

‘남길 파일 정하기’는 보존 규칙에 따라 사본을 체크합니다. 이때도 파일은 바뀌지 않습니다. ‘첫 번째 파일만 남기고 나머지 삭제’는 현재 검사 결과의 전체 중복 그룹에서 첫 파일과 보호 파일을 남기고 **즉시 실행**합니다. 추가 미리보기·확인·전체 재검사 없이 나머지를 `delete_files`로 이동합니다. 실행 시 원본 식별자와 변경 시각이 최초 검사와 다르면 중단하며, 실행 후 목록은 메모리에서 갱신합니다. 첫 번째가 최신 파일이라는 의미는 아닙니다. 안전 보관은 원래 위치에서 옮기는 방식이며 작업 기록에서 복원할 수 있지만 디스크 공간을 즉시 확보하지 않습니다.

같은 결과를 밝은 화면으로 보려면 [라이트 모드 중복 결과](comparison-light.png)를 확인하세요.

비교 탭에서는 결과를 넓게 보여줍니다. 파일 목록의 검색·종류·검사 범위는 ‘전체 파일’ 탭에서 다시 확인할 수 있습니다. 전체 검사 범위와 화면 표시 필터는 다릅니다. 자동 분류와 중복 사본 정리는 체크·화면 필터가 아닌 검사 범위에서 계획을 만듭니다.

## 규칙은 예시를 보며 편집하세요

![규칙 작성과 경로 예시](classification.png)

추천 규칙을 선택하고 이름·확장자·저장할 하위 폴더를 편집합니다. 매핑 기호 선택에서 `{종류}`, `{규칙}`, `{연도}`, `{월}` 등을 넣을 수 있습니다. 예를 들어 `청구서/{연도}/{월}`은 파일 날짜에 맞춰 하위 폴더가 달라집니다. `{수정일:%Y/%m/%d}`처럼 날짜 형식을 직접 지정할 수도 있습니다.

아래 가상 예시가 적용 조건과 예상 경로를 설명합니다. 예시는 파일을 실제로 읽거나 분류한 결과가 아닙니다. 폴더·용량·날짜 조건은 필요할 때 펼칠 수 있으며 접어도 저장된 조건은 유지됩니다. 날짜 기준은 수정일(기본) 또는 생성일입니다. 생성일이 필요한데 운영체제가 제공하지 않으면 해당 파일은 건너뛰고 이유를 알립니다. 사진 촬영일로 대신하지 않습니다.

실제 대상은 다음 미리보기에서 확인합니다. 복사는 원본이 남고, 이동·안전 보관은 원래 위치가 바뀝니다. 자동 분류 실행에는 경로 확인과 체크 확인 절차가 있으며 기존 안전 검증과 복원 기록을 유지합니다.

## 겹치는 내용은 병합 미리보기를 확인하세요

![원본을 유지하는 병합 미리보기와 겹치는 문단 수](merge.png)

같은 제목의 파일이라도 내용이 같다는 보장은 없습니다. 먼저 비교하고 병합할 파일만 체크합니다. **정리 → 체크한 파일 내용 병합**에서 새 병합본의 이름·위치와 겹치는 부분이 제거된 내용을 확인하세요.

UTF-8 `.txt`·`.md`는 완전히 같은 문단을, 같은 형식·열 제목의 `.csv`·`.tsv`는 모든 셀 값이 같은 행을 한 번씩 남깁니다. 서로 다른 내용과 처음 나타난 순서는 보존합니다. 파일은 2~20개, 각각 8 MiB·전체 32 MiB, 전체 문단·행 200,000개까지입니다. 표는 최대 1,000열·전체 1,000,000셀을 지원하며 셀 내부 줄바꿈도 보존합니다. 문장의 의미·충돌을 판단하는 자동 편집이나 이미지·Office 문서 병합은 지원하지 않습니다.

**새 병합본만 만들기**가 기본입니다. 원본을 다른 곳으로 옮기지 않으려면 이 상태로 실행하세요. **병합 후 원본을 안전 보관으로 이동**을 선택하면 검증된 병합본을 만든 뒤 원본을 보관합니다. 보관을 작업 기록에서 되돌려도 새 병합본은 남습니다. 기존 파일을 덮어쓰지 않으며, 부분 완료·실패가 나오면 병합본과 원본·보관 상태를 결과에서 확인하세요.

## 실행 결과와 복원 기록을 구분하세요

![실제 파일 처리 결과를 검색하는 실행 로그](execution-logs.png)

**기록 → 실행 로그**에서 작업 종류·상태를 고르고 파일 이름·작업 ID·오류로 실제 처리 결과를 찾습니다. 로그는 결과를 설명하며 여기서 파일을 복원하지 않습니다. **기록 → 작업 기록 · 복원**에서 원래 폴더의 기록과 보관본을 사용해 되돌립니다.

완료된 정리 작업은 경로·해시·보관 위치 같은 **복원 정보**를 자동으로 압축해 저장할 수 있습니다. 사용자가 별도로 압축하거나 파일을 고를 필요는 없습니다. 앱은 유효한 압축 정보를 우선 사용하고, 압축이 느리거나 용량 이득이 없을 때는 기존 기록 방식을 유지합니다. 압축본이 없거나 손상되면 서명된 기존 기록을 검증해 사용하며 이유를 알립니다.

자동 압축은 경로·해시 등의 복원 정보에 적용됩니다. 실제 보관 데이터도 함께 있어야 내용과 위치를 되돌릴 수 있습니다. 보관 데이터 자체를 압축·공유하는 용량 최적화는 작업 기록에서 별도로 실행합니다. `.folder-organizer` 전체를 함께 보관하세요. 압축 메타데이터만으로 이미 사라진 파일 내용이나 손상된 바이트를 새로 만들어내는 기능은 아닙니다. **도구 → 복구본 만들기**는 지원 파일에서 읽을 수 있는 내용을 새 파일로 저장하는 별도 기능입니다.

## 기능별 예시를 검색하세요

![검색 가능한 기능 안내](help.png)

기능별 주제에서 ‘언제 쓰나요 → 어떻게 사용하나요 → 실행하면 어떻게 되나요’를 읽을 수 있습니다. ‘사진’, ‘첫 번째’, ‘병합’, ‘생성일’, ‘실행 로그’처럼 궁금한 말로 검색하세요. 자세한 판정 기준은 필요한 경우에 펼칩니다.

작업 기록과 로그의 실제 화면: [작업 기록·복원](history.png), [활동 로그](logs.png). 로그는 한글 설명이 기본이며 지원용 기술 정보는 선택해서 펼칠 수 있습니다. 실제 복원은 작업 기록과 보관본을 사용하고 실행·진단 로그는 결과를 설명합니다.

개발 환경에서 같은 예시 화면을 재생성하려면 `QT_QPA_PLATFORM=offscreen python scripts/capture_ui.py`를 사용합니다. 프로젝트 의존성이 설치되어 있어야 하며 `docs`의 PNG 파일을 갱신합니다.


## 삭제 파일의 보관 위치

이 버전은 Windows·NAS의 휴지통 상태를 읽기 전용으로 확인합니다. 휴지통 조회나 NAS `#recycle` 존재만으로 파일별 복원을 보장할 수 없어, 새 삭제 파일은 모두 선택한 폴더 아래 `delete_files`로 이동합니다. 같은 이름은 덮어쓰지 않습니다. 새 삭제 작업과 복원에서는 `.folder-organizer/quarantine`과 `retained`를 만들지 않습니다. 이전 버전의 기록과 보관 데이터는 호환을 유지합니다.

NAS의 `#recycle` 폴더가 보여도 공유 폴더의 휴지통 정책·파일별 제외 조건·권한을 모두 검증한 것은 아닙니다. 이 빌드는 미검증 운영체제 삭제를 호출하지 않고 `delete_files` 보관을 사용합니다. `delete_files`, `#recycle`, `@Recycle`, `$Recycle.Bin`과 내부 작업 기록은 일반 파일 분석에서 제외합니다.

## 복원 데이터 용량 최적화

**기록 → 작업 기록 · 복원 → 복원 데이터 용량 최적화**에서 해당 작업의 보관본만 확인하고 실행합니다. 같은 1 MiB 조각은 한 번만 보관하고, 각 조각은 빠른 무손실 압축과 원시 저장 중 작은 쪽을 택합니다. 압축 효과가 부족하거나 처리 시간이 길면 기존 사본을 유지합니다.

서명된 참조와 검증된 복원 데이터를 저장한 뒤에만 중복된 보관 사본을 줄입니다. 원본이나 다른 위치의 같은 파일에 의존하지 않고 보관 데이터만으로 전체 바이트를 복원할 수 있습니다. 실제 절약량은 내용과 파일시스템에 따라 달라지며 모든 파일에서 최솟값을 보장하지 않습니다. `.folder-organizer`의 복원 객체·기록·키를 함께 유지하세요.
