# 배포·확인 원칙

사용자가 지정한 진행 원칙을 다음 변경과 배포에서도 유지합니다.

- 기존에 통과한 검사와 수정하지 않은 기존 기능의 검사는 스킵합니다. 추가 기능·UI 변경은 해당 변경에 필요한 새 사례만 확인합니다. 기존 전체 검사·과거 릴리즈 드라이버를 함께 실행하지 않습니다.
- 이미 통과한 새 사례도 사유 없이 반복하지 않습니다. 수정이나 실패로 후속 확인이 필요한 경우 해당 사례로 범위를 제한합니다.
- 정식 Windows 배포 파일은 Python판과 Rust판을 따로 제공합니다. 게시만 하는 작업에서는 빌드·검사를 반복하지 않고 확인된 ZIP을 그대로 사용합니다.
- **화면 캡처는 기본적으로 생략합니다.** 사용자가 별도로 요청한 경우에만 새 화면을 캡처합니다. v0.9.0 게시 전에 이미 생성한 화면은 당시 증거로 보존하며 이후 작업의 필수 관문으로 재사용하지 않습니다.
- 이미 공개된 태그·이전 배포 파일을 새 소스로 바꾸지 않습니다. 버전·소스·빌드 기록·체크섬을 구분해 기록합니다.

v0.9.0의 `workspace-release.yml`은 당시 완료한 배포의 기록입니다. 향후 버전에 복사해 사용할 때는 위 범위에 맞게 새 확인만 구성하고, 화면 캡처를 기본 실행하는 과거 드라이버를 호출하지 않습니다. main 커밋의 `[skip ci]`는 기존 전체 검사 자동 실행을 막기 위해 유지합니다.
