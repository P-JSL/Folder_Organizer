# 정식 Windows 배포 절차

현재 정식 버전은 v0.9.3이며 Python판과 Rust판을 별도 ZIP으로 제공합니다. [배포 원칙](RELEASE_POLICY.md)에 따라 이미 통과한 검사와 미수정 기능은 반복하지 않습니다.

## 소스와 검증 준비

1. 요청한 수정과 해당 경로의 검증을 완료하고 원시 결과·소스 해시·미검증 범위를 기록합니다. v0.9.3의 근거는 [Windows 전송 검증 기록](WINDOWS_TRANSFER_METADATA_RESULTS.json)입니다.
2. Python의 __init__·pyproject·version.json, Rust의 Cargo.toml·루트 Cargo.lock 항목·version.json을 같은 새 버전으로 맞춥니다. 이전 버전 업그레이드 확인 도구의 기준도 맞춥니다.
3. 변경 내역과 새 버전 릴리즈 노트를 준비하고 소스를 커밋합니다. 기존 전체 검사의 자동 실행을 막는 `[skip ci]`를 유지합니다. 확정 소스에 새 버전 태그를 만들며 기존 공개 태그를 이동하지 않습니다.

## 빌드와 게시

`Python and Rust package release` (`version-release.yml`)를 main의 최신 정의에서 수동 실행하고 `source_ref`에 빌드할 버전 태그를 지정합니다. 태그에서 직접 실행하면 입력을 생략할 수 있습니다. 과거 태그에 저장된 워크플로와 최신 워크플로 정의는 다를 수 있습니다.

워크플로는 Windows 체크아웃의 줄바꿈 변환을 끄고, 보존된 검증 기록과 실제 소스 해시 및 체크아웃·태그의 동일성을 확인합니다. Python·Rust를 각각 빌드하고 구성된 서명을 적용한 뒤 두 ZIP과 공통 SHA256SUMS.txt를 만듭니다. 게시 API를 부르기 전에 두 ZIP·체크섬·빌드 소스 기록을 Actions 아티팩트로 보존합니다. 초안에 업로드한 뒤 정식 최신 릴리즈로 전환하며, `stage_only=true`이면 초안 업로드까지만 수행합니다. Actions 계정에 초안 생성 권한이 없으면 기존 연결 권한으로 정확한 소스의 빈 초안을 먼저 준비합니다. 검증한 초안의 최종 게시는 같은 연결 권한으로 수행할 수 있습니다. 실제 체크아웃 SHA를 릴리즈 대상으로 사용하며 워크플로 정의의 커밋과 구분합니다.

이 워크플로는 앱 검사·CLI/GUI 실행·화면 캡처를 다시 실행하지 않습니다. 따라서 새 앱 변경을 검증하지 않은 채 사용하는 경로가 아닙니다. 코드가 바뀌어 기존 소스 근거와 다르면 필요한 검증과 근거 갱신부터 완료합니다.

게시 후 공개 ZIP을 내려받아 체크섬·압축 무결성·버전·아키텍처와 실제 빌드 소스를 확인합니다. 배포 기록에는 태그 소스, 워크플로 소스·실행 번호, 자산 해시, 서명 상태와 미검증 범위를 구분해 남깁니다. 문서 정리는 게시 후 별도 커밋으로 기록하고 이미 공개한 ZIP·태그를 덮어쓰지 않습니다.

## 과거 버전과 환경

예전 버전 전용 워크플로와 문서는 해당 Git 태그에서 확인합니다. 최신 main의 릴리즈 노트를 과거 버전의 설명으로 대체하지 않습니다. [이전 배포 파일](../DOWNLOADS/README.md)의 ZIP·체크섬·JSON 기록은 원본 그대로 유지합니다.

GitHub 앱 릴리즈와 Codex 클라우드 환경 게시는 별도 작업입니다. 앱 릴리즈 요청만으로 환경 스냅샷을 게시하지 않습니다.
