# 로그와 오류 확인

상단 **기록** 메뉴에서 목적에 맞는 화면을 선택합니다.

| 화면 | 확인할 내용 | 복원 가능 여부 |
| --- | --- | --- |
| 실행 로그 | 실제 정리·복원·병합·복구 실행의 시작, 파일별 결과, 완료·실패·부분 완료 | 결과 조회용입니다. 파일을 변경하지 않습니다. |
| 작업 기록 · 복원 | 선택한 원래 폴더의 정리 내역, 보관 위치, 파일별 결과 | 서명된 작업 기록과 보관본을 사용해 복원을 요청합니다. |
| 활동 · 진단 로그 | 분석·진행 단계·업데이트·오류 등 앱 전체 활동 | 진단용입니다. 로그만으로 파일을 복원하지 않습니다. |

**실행 로그**는 작업 종류와 상태로 필터링하고, 파일 이름·작업 ID·오류로 검색할 수 있습니다. **활동 · 진단 로그**는 수준과 검색어로 좁힐 수 있습니다. 두 로그 화면 모두 새로고침, 표시된 기록을 새 파일로 내보내기, 로그 폴더 열기를 제공합니다.

Windows 기본 위치는 `%LOCALAPPDATA%\FolderOrganizer\logs`입니다. Linux는 `$XDG_STATE_HOME/FolderOrganizer/logs` 또는 `~/.local/state/FolderOrganizer/logs`, macOS는 `~/Library/Logs/FolderOrganizer`를 사용합니다. 로그 화면의 **로그 폴더 열기**로 실제 위치를 확인할 수 있습니다.

실행 로그는 `executions.jsonl`, 활동·진단 로그는 `organizer.log`에 UTF-8로 저장합니다. 각각 기본 2 MiB 파일과 이전 파일 세 개를 순환 보관합니다. 화면은 최근 최대 1,000개, 읽기량은 최대 8 MiB로 제한합니다. 잘못된 줄은 건너뜁니다. 순환 보관으로 오래된 로그가 사라져도 선택 폴더의 실제 복원 기록이 함께 삭제되는 것은 아닙니다.

지원되는 실행 환경에서는 비정상 종료의 네이티브 스택을 별도 `crash-*.log`에 남기며 최근 세 파일을 보관합니다. 모든 종류의 강제 종료에서 기록을 남길 수 있는 것은 아닙니다.

파일 내용과 전체 작업 계획은 로그에 기록하지 않습니다. 경로·파일 이름·오류 정보는 포함될 수 있으므로 내보낸 로그를 다른 사람에게 공유하기 전에 확인하세요. 일반적인 자격 증명 필드와 문자열은 가립니다. 로그는 외부로 자동 전송하지 않습니다.

로그를 쓸 수 없더라도 파일 작업은 계속할 수 있으며 로그 화면에 저장 실패를 안내합니다. 복원이 필요하면 선택한 원래 폴더의 `.folder-organizer`와 보호 사본을 유지해야 합니다. 진단 로그만으로 원본 파일을 복구할 수는 없습니다.

## v0.5.0 검토용 후보의 압축 복원 정보

완료된 정리 작업의 복원 정보는 이득이 있을 때 `.folder-organizer/history/<작업 ID>.restore.json.gz`로 압축해 저장합니다. 현재 작업의 압축본임을 검증하는 서명된 활성 확인 정보와 기존 `<작업 ID>.json` 기록도 보관합니다. 복원 시 현재 폴더·작업 ID·서명과 내용 검증을 통과한 압축 정보를 우선 사용합니다.

압축이 느리거나 크기 이득이 적고, 지원 크기를 넘거나 저장에 실패하면 기존 기록 방식으로 진행합니다. 압축본 또는 활성 확인 정보가 없거나 손상되면 서명된 기존 JSON을 검증해 사용하고 이유를 표시합니다. 기존 JSON이 변조된 경우 압축본을 이용해 검증을 우회하지 않습니다. 유효한 압축본과 활성 확인 정보가 남아 있다면 누락된 JSON 기록을 대신해 복원할 수 있습니다.

| 보관 자료 | 역할 |
| --- | --- |
| 압축 메타데이터·서명된 작업 기록 | 원래 경로, 대상·보관 위치, 해시와 파일별 상태를 확인합니다. |
| 실제 보관 데이터 | 복원할 파일 내용을 제공합니다. 일반 보관 파일 또는 별도로 최적화한 압축 데이터이며, 압축 메타데이터만으로 사라진 내용을 재생성하지 않습니다. |
| 실행·진단 로그 | 처리 결과와 오류를 설명합니다. 복원 권한이나 파일 내용의 대체 자료가 아닙니다. |

`.folder-organizer` 안의 파일을 이름만 보고 삭제하거나 편집하지 말고 폴더 전체를 유지하세요. 자동 메타데이터 압축으로 줄어드는 것은 복원 정보의 용량입니다. 실제 보관 데이터의 최적화는 작업 기록에서 별도로 실행합니다. 손상된 파일에서 가능한 내용을 새로 저장하는 **복구본 만들기**는 작업 복원과 별개입니다.
