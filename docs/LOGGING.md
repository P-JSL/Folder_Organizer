# 로그와 오류 확인

앱의 **로그 · 작업 진단** 화면에서 작업 시작·단계·완료·실패, 정리 결과와 복원 요청을 확인할 수 있습니다. 수준과 검색어로 범위를 좁히고, 표시된 기록을 새 JSONL 파일로 내보낼 수 있습니다. 작업 기록은 실제 복원을 위한 자료이고, 로그는 진행 상황과 오류를 설명하기 위한 자료입니다.

Windows 기본 위치는 `%LOCALAPPDATA%\FolderOrganizer\logs`입니다. Linux는 `$XDG_STATE_HOME/FolderOrganizer/logs` 또는 `~/.local/state/FolderOrganizer/logs`, macOS는 `~/Library/Logs/FolderOrganizer`를 사용합니다. 로그 화면의 **로그 폴더 열기**로 실제 위치를 확인할 수 있습니다.

일반 로그는 UTF-8로 저장하며 기본 2 MiB 파일과 이전 파일 세 개를 순환 보관합니다. 화면은 최근 최대 1,000개, 읽기량은 최대 8 MiB로 제한합니다. 잘못된 줄은 건너뜁니다. 지원되는 실행 환경에서는 비정상 종료의 네이티브 스택을 별도 `crash-*.log`에 남기며 최근 세 파일을 보관합니다. 모든 종류의 강제 종료에서 기록을 남길 수 있는 것은 아닙니다.

파일 내용과 전체 작업 계획은 로그에 기록하지 않습니다. 경로·파일 이름·오류 정보는 포함될 수 있으므로 내보낸 로그를 다른 사람에게 공유하기 전에 확인하세요. 일반적인 자격 증명 필드와 문자열은 가립니다. 로그는 외부로 자동 전송하지 않습니다.

로그를 쓸 수 없더라도 파일 작업은 계속할 수 있으며 로그 화면에 저장 실패를 안내합니다. 복원이 필요하면 선택한 원래 폴더의 `.folder-organizer`와 보호 사본을 유지해야 합니다. 진단 로그만으로 원본 파일을 복구할 수는 없습니다.
