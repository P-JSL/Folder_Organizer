# 분석 속도와 진행도

## 검사 정확도를 유지하는 최적화

완전 중복 검사는 같은 크기의 파일만 비교합니다. 1 MiB 이상의 파일에는 앞·중간·끝의 제한된 표본을 먼저 읽어 **서로 다른 파일을 제외**합니다. 표본이 같더라도 중복으로 판정하지 않고 파일 전체 SHA-256과 실제 바이트 비교를 수행합니다. 읽는 동안 변경된 파일은 검사에서 제외합니다.

텍스트·이미지 특징은 앱 실행 중에만 유지되는 제한된 메모리 캐시를 사용합니다. 파일 경로·식별자·수정 상태와 열린 파일의 변경 시각을 확인하며 파일이 바뀌면 다시 읽습니다. 전체 파일의 중복 해시를 영구 저장해 검증을 생략하지 않습니다. 캐시의 기본 상한은 32 MiB·512개 항목입니다.

## 재현 가능한 측정

```sh
python scripts/benchmark_analysis.py --revision v0.2.0
python scripts/benchmark_analysis.py
```

스크립트는 임시 폴더에 크기가 같은 2 MiB 파일 68개를 만들며, 그중 완전 중복 네 쌍을 포함합니다. 생성 시간은 제외하고 분석을 세 번 반복합니다. 결과가 같은 네 그룹인지도 확인합니다. 원본 자료를 사용하거나 변경하지 않습니다.

이 클라우드 Linux 환경에서 측정한 알고리즘의 요청 읽기량은 기존 **152 MiB → 44.75 MiB**, 약 **70.6% 감소**였습니다. 관측한 중앙 분석 시간은 약 **0.119초 → 0.034초**였습니다. 이는 운영체제 캐시가 적용될 수 있는 합성 자료의 결과이며 개인 PC·HDD·네트워크 드라이브 전체의 속도 향상을 보장하지 않습니다. 같은 내용의 큰 파일이 많으면 최종 전체 검증이 필요하므로 읽기 감소 폭이 작습니다.

## 진행도 읽는 법

- 폴더 탐색 중에는 전체 파일 수를 아직 모르므로 현재 발견한 수와 경과 시간을 표시합니다.
- 표본 읽기·전체 해시·바이트 검증·규칙 적용·복사·복원처럼 전체 처리 수를 아는 단계에서는 처리 수/전체 수와 **현재 단계의 백분율**을 표시합니다.
- 단계가 바뀌면 백분율 기준도 바뀝니다. 모든 단계를 합친 가상의 백분율을 표시하지 않습니다.
- 남은 시간은 충분한 측정이 있는 현재 단계의 추정치입니다. 큰 파일 하나나 느린 저장 장치에서는 처리 개수 기준 추정과 실제 시간이 다를 수 있습니다.
- 전체 파일 수가 같아도 크기와 저장 장치에 따라 시간이 다릅니다. 취소한 분석의 부분 결과는 정리 실행에 사용하지 않습니다.
