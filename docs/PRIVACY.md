# 개인정보·로컬 데이터 안내

제정일·문서 버전: 2026-10-29 / 1.0

이 문서는 Folder Organizer Python판·Rust판의 현재 데이터 처리 방식과 이용자가 확인할 내용을 설명합니다. 이용 권한과 저작권은 [LICENSE](../LICENSE), 상세 이용 조건은 [이용약관](TERMS_OF_USE.md)을 따릅니다. ZIP에서는 앱 폴더의 `LICENSE`와 이 문서가 함께 제공되는 `licenses/FolderOrganizer/`를 참고하세요.

## 1. 파일 처리 위치와 데이터 권리

파일 분석·비교·정리·병합·복구는 사용자가 선택한 로컬 저장소 또는 NAS·공유 폴더 등에서 수행합니다. 이 앱은 파일 본문·이미지·비교 미리보기를 프로그램 권리자의 서버로 자동 업로드하지 않습니다. 사용자 파일의 소유권과 이용 권한은 정당한 권리자에게 남습니다.

NAS나 조직의 공유 폴더를 선택하면 해당 저장소를 운영하는 주체의 접근·보관·백업·감사 정책이 함께 적용될 수 있습니다. 사용자가 직접 내보낸 보고서나 외부에 공유한 파일의 처리 방식도 공유한 서비스와 수신자의 정책에 따릅니다.

## 2. 앱이 기기에 보관하는 정보

| 항목 | 포함될 수 있는 정보 | 목적 |
| --- | --- | --- |
| 설정·최근 폴더 | 화면 설정, 선택 경로, 제외 조건, 보호 폴더, 분류 규칙, 업데이트 설정 | 사용자가 지정한 환경 유지 |
| 분석·비교 결과 | 파일 경로·이름·종류·크기·날짜·해시, 비교 점수와 경고 | 파일 목록·중복·유사 후보 표시 |

프로그램 설정과 로그는 운영체제의 앱 설정 경로 등에, 작업·복원 데이터는 작업 폴더 및 앱이 안내하는 보관 경로에 저장됩니다. Python판과 Rust판의 기록은 구분됩니다. 구체적인 파일 경로와 복원 범위는 README 및 앱 안내를 참고하세요.

파일 이름·폴더 경로 자체에 실명·기관명·업무 정보가 포함될 수 있습니다. 로그와 보고서를 공개하기 전에 내용을 확인하세요. 복원용 인증 키나 개인 데이터는 공개 저장소·이슈·메신저의 공개 채널에 올리지 마세요.

## 3. 자동 업데이트와 외부 통신

업데이트 기능은 GitHub의 릴리즈 API에 접속하여 새 버전 정보를 확인합니다. 두 판 모두 기본 설정에서 자동 확인을 사용합니다. Python판은 자동 확인에서 새 버전을 찾으면 배포 ZIP과 체크섬을 자동으로 내려받아 앱 종료 후 적용할 준비를 합니다. Rust판은 새 버전을 안내한 뒤 사용자가 다운로드를 선택하면 파일을 내려받습니다. 통신 과정에서 IP 주소·접속 시각·요청 주소·앱의 User-Agent 등 통상적인 접속 정보가 GitHub 및 관련 배포 인프라에 전달될 수 있습니다. 파일 본문이나 개인 폴더 목록을 업데이트 요청의 내용으로 보내는 기능은 없습니다.

자동 업데이트 확인 여부는 앱 설정에서 조정할 수 있습니다. 사용자가 직접 실행하는 업데이트 확인이나 다운로드는 별도의 요청입니다. GitHub 등 외부 서비스의 접속 정보 처리에는 해당 서비스의 정책이 적용됩니다. 사용자가 구성한 프록시·VPN·보안 소프트웨어의 정책도 영향을 줄 수 있습니다.

## 4. 이용허락 요청과 지원 문의

허락·지원 요청을 사용자가 직접 보내는 경우, 권리자는 답변과 허락 범위 확인에 필요한 연락 수단·사용자 식별자·목적·조직·허락 기록 및 사용자가 선택해 첨부한 자료를 받을 수 있습니다. 현재 앱에 이를 자동 수집해 송신하는 기능을 추가하는 문서가 아닙니다.

요청에는 GitHub 사용자명 등 답변에 필요한 최소한의 식별자만 사용하세요. 주민등록번호·신분증·계정 비밀번호·인증 토큰·결제 수단이나 실제 개인 파일은 요청하지 않습니다. 민감한 정보가 필요한 사안은 공개 이슈 대신 권리자와 합의한 비공개 수단을 사용하세요. [요청 안내](PERMISSION_REQUEST.md)에 최소 양식을 제공합니다.

수동으로 제공된 정보는 요청 처리와 허락·분쟁 기록 등 필요한 목적의 범위에서 취급하며, 목적 달성·삭제 요청 시 적용 법령과 정당한 보관 필요를 고려해 처리합니다. 법적 의무나 분쟁 대응을 위해 보관이 필요한 부분은 그 범위와 이유를 구분해야 합니다. 정정·삭제·요청 철회는 자료를 전달한 수단 또는 권리자가 안내한 수단으로 요청할 수 있습니다.

## 5. 보관·삭제와 복원 데이터

사용자는 기기에 보관된 설정·로그·보고서를 관리할 수 있습니다. 다만 작업 기록·인증 키·`delete_files`·백업·압축 보관 데이터를 삭제하거나 분리하면 해당 작업의 복원이 불가능해질 수 있습니다. 원본과 별도의 백업을 확보하고 필요한 복원 작업을 마친 뒤 보관 정책을 정하세요.

프로그램의 이용허락 종료만으로 원본 파일이나 복원 기록의 파기를 요구하지 않습니다. 이 약관은 원격 삭제·감시·개인정보 판매·광고 추적에 대한 동의가 아닙니다.

## 6. 문서 변경

데이터 처리 방식이 변경되면 변경 시점과 내용을 문서에 반영합니다. 새로운 개인정보 처리나 동의가 필요한 기능을 도입할 경우 해당 법령과 필요한 고지·동의 절차를 따릅니다. 이 문서만으로 현재 구현되지 않은 수집·보관·보안 기능이 제공된다고 보장하지 않습니다.
