# v0.7.0 실제 배포 결과

두 Windows x64 정식 배포본을 [v0.7.0](https://github.com/P-JSL/Folder_Organizer/releases/tag/v0.7.0)에 공개했습니다. 실행 파일 소스와 변경 불가능한 태그는 `664e574a772fda1a41b28e4bad577773c4862d1f`입니다. 이후 콘솔 출력·결과 재사용·게시 절차만 수정했으며 실행 파일을 다시 만들지 않았습니다.

## 실제 파일

| 판 | ZIP 바이트 | 비압축 바이트 | 파일 수 |
| --- | ---: | ---: | ---: |
| Python | 57,137,991 | 128,682,922 | 248 |
| Rust | 8,532,744 | 20,974,328 | 426 |

Python ZIP은 이용약관을 포함한 직전 0.6.1의 99,280,942바이트에서 약 42.4% 줄었습니다. Qt 전체 데이터 수집을 제거한 결과이며 이미지 코덱·Windows 플랫폼·소프트웨어 렌더링·법적 문서는 유지했습니다. 두 판은 패키지 구성이 달라 파일 수만으로 기능이나 성능의 우위를 판단하지 않습니다.

ZIP SHA-256:

- Python: `6a8c93e9519c57601ee99986d672c6f475199a88a4e838b786086b2081c6ed75`
- Rust: `f327320bee1eded504e13ea8ffa9b6aff79bc998741602fdb7b8f9ae01904873`

선택적 서명 설정을 보존했지만 실제 이번 빌드에는 인증서가 설정되지 않았습니다. 5개 실행 파일의 Authenticode 상태는 모두 `NotSigned`이며 공인 게시자 서명을 제공하지 않습니다.

## 같은 입력의 새 Windows 측정

Windows Server 2025, Python 드라이버 3.12에서 실제 배포 CLI를 입력별·판별 5회씩 번갈아 실행한 중앙값입니다. 전체 20회 실행은 시작·폴더 조회·완전 중복 검사·공통 JSON 출력을 포함합니다. [원시 측정 자료](EDITIONS_BENCHMARK_0.7.0.json)에 정확한 플랫폼·소스·실행 파일 해시와 모든 관측값이 있습니다.

| 임시 입력 | Python 시간 | Rust 시간 | Python peak private commit | Rust peak private commit |
| --- | ---: | ---: | ---: | ---: |
| 작은 파일 1,006개, 1,024,128바이트 | 1.6474초 | 0.3768초 | 23,359,488 B | 4,177,920 B |
| 4 MiB 파일 12개, 총 48 MiB | 0.2844초 | 0.0492초 | 22,568,960 B | 9,707,520 B |

각 실행에서 정답 중복 그룹·조회 범위·크기·종류·확장자·수정 시각이 일치했습니다. 두 판에서 생성 시각도 모두 제공되어 1,006개/12개 각각의 나노초 값을 대조했고 원본 바이트는 보존됐습니다. 샘플만 같고 실제 내용이 다른 파일은 중복 그룹에 들어가지 않았습니다.

대형 입력에서 두 판 모두 샘플 2,359,296바이트를 읽고 4개 파일의 전체 해시 16,777,216바이트만 읽었습니다. Rust는 해시 과정에서 보존한 바이트를 비교해 추가 디스크 바이트 비교 읽기는 0이며, Python의 추가 바이트 비교 읽기는 8,388,608바이트입니다. 추가 읽기 0은 바이트 검증 생략을 뜻하지 않습니다.

이 표는 **현재 두 판 사이의 해당 합성 입력 비교**이며 0.6.1 대비 실행 속도 개선 배수가 아닙니다. 캐시를 비우지 않았고 입력 생성·해시 확인이 캐시를 따뜻하게 할 수 있습니다. 실제 NAS·물리 SSD/HDD·콜드 캐시·10만 행 GUI는 측정하지 않았습니다. 메모리는 20ms 관측의 Windows high-water 카운터이며 private bytes·working set·물리 저장 장치 I/O와 같은 지표가 아닙니다.

## 통과한 검사와 재사용

새 로컬 사례 45건(Python 13, Rust 32)과 새 Windows 사례 3건이 통과했습니다. Windows 사례는 긴 Unicode 경로의 샘플 선별, 같은 수정 시각을 유지한 파일 교체, 취소된 복사 후 외부 하드링크를 보존하는 복원을 다룹니다. 수정하지 않은 기능과 기존에 통과한 검사는 실행하지 않았습니다.

실제 Python ZIP의 이미지 형식·조회·중복·원본 보존·GUI 표시와 종료도 완료됐습니다. 마지막 결과를 콘솔에 출력할 때 cp1252 인코딩 오류가 발생해 ASCII 출력으로 수정했습니다. 앱·검사 로직이 그대로임을 확인하고 완료한 검사를 재사용했습니다. 해당 첫 실행의 PNG와 원본 JSON은 업로드되지 않았으므로 화면을 첨부하거나 치수·색상 수를 추정하지 않습니다. Rust GUI 실행과 위 20회 비교는 이후 별도로 성공했습니다.

- [정식 빌드와 새 Windows 사례](https://github.com/P-JSL/Folder_Organizer/actions/runs/40943399617)
- [완료한 배포본 검사·측정](https://github.com/P-JSL/Folder_Organizer/actions/runs/40944704868)
- [성공한 게시 전용 작업](https://github.com/P-JSL/Folder_Organizer/actions/runs/40945890352): 빌드·프로그램 검사 모두 스킵

Actions의 릴리즈 생성 요청은 403으로 거부되어 정확한 태그의 빈 초안을 먼저 만들었습니다. 게시 전용 작업은 성공한 빌드·검사 기록과 실행 파일 해시를 확인한 뒤 기존 ZIP을 덮어쓰기 없이 업로드하고 정식 최신 릴리즈로 공개했습니다. 과거 태그·배포 파일은 변경하지 않았습니다. 상세 영수증·서명 상태·패키지 목록·측정 원본·출력 오류와 재사용 근거는 릴리즈의 `VALIDATION_RESULTS.zip`에 포함합니다.
