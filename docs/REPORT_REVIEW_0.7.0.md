# v0.6.1 비교 보고서에 대한 코드 검토와 v0.7.0 반영

검토 대상: 사용자가 제공한 `FolderOrganizer_v0.6.1_정밀비교_분석보고서.pdf` 11쪽. 보고서는 검토 자료로 취급했으며, 문서의 재현 명령을 그대로 실행하거나 그 권고를 이미 검증된 사실로 간주하지 않았습니다.

보고서의 기준 소스는 `4c05dfb`이며 원본 ZIP 해시는 Python `94939d3b…`, Rust `aae03410…`입니다. 이후 약관 문서가 추가된 v0.6.1 ZIP은 해시·용량·파일 수가 달라졌으나 실행 파일은 유지되었습니다. 따라서 보고서의 수치는 그 원본 배포본에 대한 기록이며 현재 다운로드의 정확한 용량으로 재사용하지 않습니다.

## 추가로 발견해 수정한 문제

취소된 복사·이동의 대상 파일이 아직 게시되지 않았는데도, 사용자가 나중에 그 경로에 만든 원본 하드링크를 앱의 복사본으로 오인할 수 있었습니다. 복사본의 게시 증거와 검증된 staging 식별을 따로 요구하여 해당 파일을 건드리지 않도록 수정했습니다. 실제로 게시한 뒤 기록 저장이 중단된 복사본의 복원은 유지합니다.

이전 Rust 0.6.0 수정 ZIP에는 앱 루트에 `BUILD_INFO.json`이 있었지만 새 업데이터의 일반 파일 허용 목록에는 없었습니다. 새 업데이터에서는 공식 배포했던 정확한 문서의 CRLF/LF 해시만 인식합니다. 임의 JSON·추가 개인 내용·중복 키를 허용하지 않습니다. **이미 설치된 구형 실행 파일의 코드를 소급 변경할 수는 없으므로 해당 0.6.0 설치는 최초 한 번 수동 업그레이드가 필요합니다.**

Python CLI에서 `--duplicates --similar`를 함께 요청하면 유사도 내부에서 중복을 다시 계산하던 경로도 확인했습니다. 현재 프로세스에서 인증된 그룹과 전체 스냅샷을 재확인해 결과를 재사용하며, 내보낸 보고서는 실행 권한이 되지 않습니다.

공통 보고서 구현도 별도로 대조했습니다. 일부 결과인데 HTML 제목은 완료처럼 표시되는 경우, `--similar` 단독 실행의 `duplicates.requested` 의미 차이, 미요청 항목의 `null`/빈 컨테이너 차이를 수정합니다. 단순히 같은 스키마 이름만 붙이는 것으로 정합성을 인정하지 않습니다.

## 정확성과 속도에 대한 경계

- 샘플이 같아도 중복을 확정하지 않습니다. 샘플 밖만 다른 사례와 캐시 한도를 넘는 실제 바이트 비교를 새 검사에 포함합니다. 샘플 후 바뀐 파일도 조용히 비중복으로 확정하지 않습니다.
- 읽기 계측은 함수가 실제 요청해 받은 표본·전체 해시·바이트 비교의 바이트 수입니다. 물리 디스크가 읽은 바이트나 NAS 전송량과 같다고 주장하지 않습니다.
- 유사도 인덱스는 내용 특징을 읽는 비용을 추가합니다. 누락을 줄일 수 있지만 모든 입력에서 기존 이름 인덱스보다 빠르다고 보장하지 않습니다.
- 골든 코퍼스의 precision/recall은 그 라벨·입력에만 해당합니다. 원래 픽셀 노이즈 사례도 보존했으며 16개 선택 쌍 중 14개가 유사 후보로 반환됩니다. 축소 후 고주파·균일 패턴의 특징이 겹치는 한계를 경고하고, 실제 바이트 중복·자동 삭제 권한과 분리합니다.
- 폴더 전체 탐색에는 최소 각 엔트리 방문과 경로·메타데이터 처리가 필요합니다. 일반적인 전체 결과를 보장하면서 O(n) 아래의 탐색을 약속하지 않습니다. 정렬·전체 파일 내용 읽기 비용도 별도입니다.

## 검사와 측정 정책

사용자 지시에 따라 수정하지 않은 기능과 이미 통과한 검사는 생략합니다. 이번에 바꾼 중복 선별·부분 오류·증명 재사용·내용 후보·CLI/보고서·복원 대상 식별·패키징에 새 입력과 실패 사례만 추가합니다. 작업 파일은 테스트용 임시 폴더에만 생성합니다.

`scripts/benchmark_editions_v070.py`는 두 실제 배포 CLI를 같은 호스트·입력에서 최소 5회씩 순서를 바꿔 실행합니다. 새 프로세스 시작·목록·중복 검사·공통 JSON 내보내기를 포함한 합성 작업의 벽시계·CPU·가능한 Windows 프로세스 메모리·I/O를 기록합니다. OS 캐시를 비우지 않으며 입력 생성·해시 확인이 캐시를 따뜻하게 할 수 있습니다. Private Bytes, peak private commit, working set, 알고리즘 읽기량, 프로세스 I/O를 서로 같은 지표처럼 해석하지 않습니다. 실제 NAS·물리 SSD·콜드 캐시·GUI 10만 행의 결과로 확대하지 않습니다.

최종 배포 파일의 실행 결과와 측정 자료는 [실제 배포 결과](RELEASE_RESULTS_0.7.0.md), [원시 Windows 측정](EDITIONS_BENCHMARK_0.7.0.json) 및 릴리즈 첨부 기록으로 제공합니다. 원래 PDF의 실행 미측정 부분을 추정 수치로 채우지 않습니다. 새 로컬 45건·Windows 3건이 통과했으며 기존 통과 검사와 미수정 기능 검사는 생략했습니다.
