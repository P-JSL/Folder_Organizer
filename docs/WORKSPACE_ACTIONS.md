# 단일·다중 폴더 검사와 정리 — 개발 소스 안내

이 문서는 v0.9.0 이후 개발 소스의 통합 작업 공간을 설명합니다. **최신 공개 릴리즈는 v0.7.0으로 롤백한 상태**이며, DOWNLOADS에 보관한 v0.9.0 ZIP에는 이 개발 변경이 들어 있지 않습니다. 새 공개 릴리즈는 게시하지 않습니다.

## 화면 구성

첨부 참고 화면의 작업 흐름을 따라 필요한 기능을 모았습니다. 기존 앱의 이름·도움말·다크/라이트 모드는 유지합니다.

| 위치 | 사용할 기능 |
| --- | --- |
| 상단 리본 | 폴더 추가·분석 시작·중지, 중복·유사 검사, 체크, 정리, 보고서·도구 |
| 왼쪽 | 분석할 폴더 체크 목록과 검사 범위·제외 조건 |
| 가운데 | 전체 파일·완전 중복·유사 후보와 파일 체크 |
| 오른쪽 | 선택 파일의 이름·전체 경로·용량·날짜, 그룹 근거 |
| 아래 | 파일 종류별 개수·용량 요약, 진행·완료·부분 실패 상태 |

폴더가 한 개여도 같은 화면을 사용합니다. 여러 폴더의 결과를 보기 위해 별도 창으로 이동하거나, 정리하려고 단일 폴더 화면으로 다시 옮길 필요가 없습니다. 파일 정보와 요약은 분석 결과에서 표시하며 화면을 그릴 때마다 파일 내용을 읽지 않습니다.

## 분석에서 정리까지

1. 폴더를 추가하고 검사할 위치를 체크합니다. 경로를 목록에서 제거하는 것은 실제 폴더를 삭제하는 동작이 아닙니다.
2. 범위를 확인하고 분석을 시작합니다. 완료된 현재 분석에서 파일 목록과 완전 중복을 확인합니다. 취소·접근 실패가 있으면 상태와 범위를 먼저 확인합니다.
3. 유사 검사는 별도로 실행합니다. 유사 후보는 검토 대상이며, 이름이나 점수만으로 완전 중복이라고 판단하지 않습니다.
4. 원하는 파일을 체크하고 복사·이동·삭제 보관·규칙 분류를 선택합니다. 일반 정리는 원본·대상 경로가 표시된 미리보기를 확인한 뒤 실행합니다. 숨겨진 체크 항목과 현재 선택 수를 함께 확인하세요.
5. 완료·실패·취소 내역을 확인합니다. 작업으로 현재 분석의 상태가 바뀌면 새 분석이 필요하다는 안내를 따릅니다. 이전 계획이나 내보낸 보고서를 가져와 다시 실행하지 않습니다.

내용 병합은 여러 원래 폴더에서 선택한 지원 UTF-8 텍스트·Markdown·CSV·TSV에도 사용할 수 있습니다. 기존의 파일 수·용량·형식 제한 안에서 겹치는 문단·행을 정리한 **새 파일**을 미리 확인합니다. 원본 유지가 기본이며, 원본 보관을 선택하면 새 출력의 검증이 끝난 뒤 실제 원본 폴더별 `delete_files`와 작업 기록으로 이동합니다. 두 파일 나란히 비교와 여러 파일 병합의 선택 범위는 별도로 유지합니다.

## 첫 파일만 남기고 나머지 삭제

이 버튼은 **현재 앱에서 검증한 완전 중복 그룹 전체**에 적용됩니다. 여러 폴더에 같은 내용이 있어도 폴더마다 한 개씩 남기는 것이 아니라 **그룹 전체의 첫 파일 한 개와 보호 대상**을 남깁니다. 유사 후보에는 적용하지 않습니다.

클릭하면 기존의 인증된 중복 근거를 사용하므로 추가 전체 재검사·재해시·확인 창을 실행하지 않습니다. 파일 식별 정보와 변경 시각 확인은 유지하며, 원본이나 사본이 바뀌었으면 실행을 거부합니다. 파일 내용을 추측하거나 이름만 보고 삭제하지 않습니다.

직접 체크한 파일을 삭제 보관하는 동작은 별개입니다. 그 선택을 완전 중복으로 새로 인증하는 것이 아니므로 일반 정리 미리보기에서 대상 경로를 확인합니다.

## 여러 폴더의 기록과 복원

하나의 가상 공통 폴더를 만들어 작업하지 않습니다. 파일은 분석에서 정해진 실제 소속 폴더로 한 번만 연결하고, 겹친 폴더를 등록했더라도 같은 경로를 중복 처리하지 않습니다.

- 삭제 보관 위치는 파일의 실제 소속 폴더 아래 `delete_files`입니다. Windows·NAS 휴지통 이동으로 표시하지 않습니다.
- 작업·복원 기록도 실제 원본 폴더별로 남습니다. 해당 폴더의 기록에서 되돌리며, `delete_files`와 앱의 기록·키·복원 데이터를 함께 보관해야 합니다.
- 다른 폴더의 파일을 보존 원본으로 사용하는 중복 정리도 그 원본이 다른 작업 대상이나 대상 경로와 충돌하지 않는지 확인합니다.
- 여러 원본의 대상 이름이 겹치면 미리보기 단계에서 다른 경로를 예약합니다. 기존 파일을 덮어쓰지 않습니다.
- 실제 정리에 참여하는 원본·보존 폴더의 잠금과 전체 계획의 실행 전 확인을 마친 뒤 순서대로 작업합니다. 조회만 한 다른 폴더에 작업 기록을 만들지 않습니다. 중간 실패·취소 시 앞서 완료한 작업은 기록과 함께 남으며, 아직 실행하지 않은 파일을 완료로 표시하지 않습니다. 여러 폴더를 하나의 원자적 거래처럼 되돌렸다고 주장하지 않습니다.

통합 JSON 보고서는 계속 `action_authority=false`입니다. 파일 변경 권한은 현재 프로세스의 분석 세션과 서명된 작업 계획에만 있으며, 보고서를 수정하거나 다시 읽는 것으로 부여되지 않습니다.

## 확인·배포 범위

기존에 통과한 검사와 미수정 기능 검사는 모두 스킵합니다. 새 통합 작업·화면 연결에 필요한 사례만 확인하며 화면 캡처는 진행하지 않습니다. 공개 릴리즈·원본 다운로드의 상태는 [Releases](https://github.com/P-JSL/Folder_Organizer/releases)와 [DOWNLOADS](../DOWNLOADS/README.md)에서 확인하세요.
