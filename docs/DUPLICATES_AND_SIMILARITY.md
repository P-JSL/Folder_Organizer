# 중복과 유사는 어떻게 다른가

**중복은 파일 전체 내용이 같은 경우이고, 유사는 특정 특징이 가까운 검토 후보다.** 이름·날짜·용량·유사도 숫자 하나만으로 두 파일이 같거나 지워도 된다고 판단하지 않는다.

## 실제 예로 구분하기

| 두 파일의 상태 | 내용이 완전히 같은 중복인가 | 가능한 유사 근거 | 사용자가 확인할 점 |
| --- | --- | --- | --- |
| `보고서.txt`와 이름만 바꾼 `최종본.backup`의 모든 바이트가 같다 | 그렇다. 이름·확장자가 달라도 내용 비교가 증명할 수 있다. | 이름이 닮지 않아도 중복으로 찾을 수 있다. | 어느 경로를 다른 프로그램이 참조하는지 확인하고 보존할 파일을 고른다. |
| 서로 다른 폴더의 `계약서.docx`가 이름·용량만 같다 | 그것만으로는 알 수 없다. | 이름 후보일 수 있다. | 같은 크기의 다른 내용도 가능하다. 버전·당사자·서명 등을 직접 확인한다. |
| 사진을 JPEG로 다시 압축하거나 PNG로 바꿨다 | 바이트가 달라지면 완전 중복이 아니다. | 모양·색상·가로세로 비율이 비슷한 이미지 후보일 수 있다. | 해상도·편집 결과·메타데이터를 비교한다. 용량이 큰 쪽이 항상 더 좋은 사진은 아니다. |
| 문장의 일부를 수정하거나 공백만 바꿨다 | 바이트가 다르면 완전 중복이 아니다. | 지원되는 UTF-8 텍스트 특징이 비슷할 수 있다. | 변경된 문장·숫자·순서와 비교 대상의 전체 내용을 확인한다. |
| `설치파일-1.0.exe`와 `설치파일-2.0.exe`가 비슷한 이름을 가진다 | 실제 내용이 같다는 검증 없이는 아니다. | 이름 후보만 만들 수 있다. | 버전·기능·라이선스·실행 환경이 다를 수 있다. 미리보기에서 실행하지 않는다. |
| 같은 문서를 PDF와 DOCX로 저장했다 | 파일 바이트는 보통 다르다. | 이 앱이 문서 의미를 이해해 같은 문서라고 증명하지는 않는다. | 지원되는 비교 근거가 없으면 직접 문서를 확인한다. |

## 정확한 중복 검사

1. **같은 파일 크기**끼리 후보를 좁힌다. 같은 크기는 필요조건일 뿐 내용 일치의 증거가 아니다.
2. 각 파일 전체의 **SHA-256**을 계산한다. 읽을 수 없거나 분석 뒤 바뀐 파일은 같은 해시로 취급하지 않는다.
3. 해시가 같은 후보도 **실제 바이트를 다시 비교**한 뒤 완전 중복으로 표시한다.
4. 같은 물리 파일을 가리키는 하드링크 별칭은 추가 사본처럼 세지 않는다. 빈 파일은 완전 중복일 수 있지만 정리해도 내용 용량은 0바이트다.

내용이 같아도 각 경로의 역할까지 같다는 뜻은 아니다. 바로가기·프로젝트·다른 프로그램이 특정 경로를 참조할 수 있다. 보존 규칙은 사용자의 선택을 돕는 도구이고, 앱은 변경 전 미리보기를 거친다.

## 유사 검사의 세 가지 근거

| 근거 | 비교하는 것 | 강한 근거가 아닌 경우와 한계 |
| --- | --- | --- |
| **이름 유사** | 대소문자·구분자·일부 복사본 표기 등을 정규화한 이름의 글자 배열 | 같은 양식의 이름을 쓰는 전혀 다른 파일도 높게 나올 수 있다. 내용이 같다는 근거가 아니다. |
| **텍스트 유사** | 지원되는 작은 UTF-8 텍스트의 단어 묶음과 길이 등의 특징 | 공백·일부 순서 차이가 반영되지 않을 수 있다. 문서의 의미, 법적 효력, 수치의 정확성을 해석하지 않는다. PDF·Office 문서를 텍스트 의미로 자동 비교하는 기능은 아니다. |
| **이미지 유사** | 디코딩한 이미지의 구조·축소된 색상·투명도·가로세로 비율 | 축소 비교에서 작은 글자·워터마크·세부 수정이 드러나지 않을 수 있다. 같은 인물·장면을 이해하는 의미 인식이 아니다. 모든 회전·크롭·편집을 찾아낸다고 보장하지 않는다. |

이름 근거가 높아도 내용 근거가 다르면 그 차이를 확인해야 한다. 반대로 이름이 전혀 달라도 지원되는 텍스트·이미지 근거가 유사 후보를 찾는 데 도움이 될 수 있다. 서로 다른 비교 방법의 점수는 같은 척도가 아니므로 직접 서열을 매기는 근거로 쓰지 않는다.

### 유사도 100%도 완전 중복이 아닐 수 있다

유사도는 **선택한 특징 비교의 점수**이며 '두 파일이 같을 확률'이 아니다. 예를 들어 공백을 정규화한 텍스트 특징이나 축소 이미지 특징은 같아도 원본 바이트는 다를 수 있다. 이름 점수 100%는 정규화된 이름이 같다는 뜻일 뿐이다. 완전 중복 표시는 별도의 전체 바이트 검증이 있어야 한다.

엄격함을 높이면 가까운 후보만 남고, 낮추면 검토할 후보와 오탐 가능성이 함께 늘어난다. 기준 미만이거나 검사 범위를 벗어난 파일을 '서로 다름이 증명된 파일'이라고 해석해서는 안 된다.

## 0.2 버전의 근거 표시와 검사 설정

이름·텍스트·이미지 비교를 각각 선택하고 각각의 후보 기준을 지정할 수 있다. 기본 기준은 이름 **82%**, 텍스트 **90%**, 이미지 **90%**다. 검사 프로필은 여러 옵션을 한 번에 고르는 시작점이며, 어떤 프로필도 삭제 안전성이나 파일 품질을 보증하지 않는다. 설정은 현재 컴퓨터의 사용자 설정에 저장한다.

결과에는 사용한 방법, 각 방법의 점수·후보 기준, 기준을 통과한 신호와 한계가 남는다. 예를 들어 이름이 100%, 텍스트가 93%인 경우 이름 점수가 텍스트 근거를 가리지 않는다. 지원 형식·크기·선택한 방법 때문에 비교하지 않은 점수는 0%로 꾸미지 않고 **계산되지 않음**으로 구분한다.

전체 바이트 동일 여부도 다음과 같이 구분한다.

| 상태 | 뜻 |
| --- | --- |
| **같음** | 별도의 전체 크기·SHA-256·실제 바이트 검증이 일치했다. |
| **다름** | 크기가 다르거나 실제 바이트가 다르다는 근거가 있다. 유사할 가능성은 남아 있다. |
| **확인되지 않음** | 전체 바이트 비교를 완료하지 못했다. '같음'이나 '다름'을 추측하지 않는다. |

유사 검색도 먼저 완전 중복 검증을 수행하고 **검증된 완전 중복 쌍을 유사 결과에서 제외**한다. 완전 중복은 중복 검사에서 검토하고, 유사 결과에서는 내용이 다른 가까운 후보를 검토한다. 유사 쌍 수 제한은 이 사전 검증 이후의 유사 비교 단계에 적용된다. 따라서 쌍 수 제한을 작게 설정해도 대용량 파일의 사전 해시 읽기 시간까지 줄어드는 것은 아니다.

자동 유사 후보는 일반 파일에서 같은 확장자끼리, 지원 이미지에서는 다른 이미지 형식 사이에서도 비교한다. 지원 형식 전체의 의미를 해석하거나 모든 형식 조합을 비교하는 기능은 아니다.

## 두 파일 비교 화면에서 확인할 것

지원되는 비교 화면은 두 파일의 경로·크기·수정일·실제 생성일과 **전체 SHA-256**을 제공하고, 현재 바이트 일치를 별도로 확인한다. 선택한 파일이 검사 후 변경되거나 교체되었다면 오래된 결과를 근거로 계속 비교하지 않고 다시 분석해야 한다.

- **텍스트:** UTF-8 텍스트를 나란히 보고 행 단위 차이를 확인한다. 비교 파일은 최대 256 KiB이며 점수는 앞 4,096단어의 특징을 사용한다. 화면 텍스트·차이 표시에는 별도 제한이 있으므로 생략 안내가 있으면 원본 전체를 확인한다. 표시 제한 때문에 전체 바이트 검증까지 생략되는 것은 아니다.
- **이미지:** 최대 4,000만 픽셀·64 MiB 범위에서 EXIF 방향을 반영하고 최대 512×512 크기의 미리보기를 만든다. 원본 해상도도 함께 확인한다. 애니메이션은 첫 프레임만 보여주고, 모든 프레임이 같다고 판정하지 않는다.
- **다른 형식:** 메타데이터와 전체 바이트 결과를 확인한다. 실행 파일·매크로·외부 뷰어를 미리보기 과정에서 실행하지 않는다. 표시할 수 없는 내용은 명시적으로 구분한다.

텍스트의 공백만 달라 특징 점수가 같거나 이미지 축소 특징이 같아도, 바이트 결과가 다르면 비교 화면에서 완전 중복으로 표시하지 않는다.

## 정확한 중복의 보존 규칙

보존 규칙은 파일을 변경하지 않고 체크 상자 선택안을 만든다. 유사 후보에는 적용하지 않는다.

| 보존 기준 | 선택 방법 | 주의점 |
| --- | --- | --- |
| 경로순 첫 파일 | 정해진 경로 순서의 한 파일을 남김 | 최초 생성된 원본이라는 뜻은 아니다. |
| 최근 수정 파일 | 수정 시각이 가장 최근인 파일을 남김 | 생성일·품질·내용의 정답 여부와 다르다. |
| 오래된 수정 파일 | 수정 시각이 가장 오래된 파일을 남김 | 처음 만들어진 원본이라는 보장은 없다. |
| 짧은 경로 | 상대 경로 길이가 짧은 파일을 남김 | 프로그램이 사용하는 경로를 자동 파악하지 않는다. |
| 선호 폴더 | 지정한 폴더 안의 사본을 우선 남김 | 그 폴더에 사본이 없으면 경로순으로 선택하고 안내한다. |

**보존 규칙의 자동 선택은 보호 폴더 안의 사본을 모두 남긴다.** 보호 사본이 여러 개면 그룹에 여러 파일이 남을 수 있다. 그룹별 최소 한 파일을 남기는 규칙보다 보호 폴더를 우선하며, 보호 폴더가 있다고 파일을 자동 이동·삭제하지 않는다. 직접 체크한 파일까지 변경 불가로 만드는 접근 제어 기능은 아니다. 파일이 변경되거나 그룹이 모호하면 해당 그룹 전체의 자동 선택을 건너뛴다. 최종 변경은 기존 작업 미리보기와 확인 절차를 따른다.

## 검사 범위와 보고서

제외할 상대 경로·이름 패턴과 최소/최대 파일 크기로 실제 검사 범위를 정할 수 있다. 예를 들어 `*.tmp`, `Cache`, `Backup/**`를 제외할 수 있다. 하위 폴더·숨김 파일 포함 여부도 검사 범위에 영향을 준다. **화면 검색창과 종류 필터는 표시만 바꾸며 검사 범위를 바꾸지 않는다.** 범위 설정을 변경했다면 다시 분석해 적용해야 한다.

분석 보고서는 파일 목록뿐 아니라 판정 근거·사용한 비교 기준·검사 범위·실제 비교 수·제한 도달·경고를 확인하는 용도다. 한도에 도달하거나 검사할 수 없는 파일이 있었다면 결과 수가 적다는 이유로 폴더가 완전히 정리됐다고 판단하지 않는다.

## 검토와 선택 순서

1. **판정 유형과 근거를 읽는다.** 완전 중복인지 이름·텍스트·이미지 후보인지 확인한다.
2. **두 파일을 비교한다.** 경로·크기·수정일·실제 생성일, 지원되는 미리보기와 내용 차이를 확인한다. 생성일이 제공되지 않는 운영체제에서는 확인 불가로 표시한다.
3. **보존할 파일을 먼저 정한다.** 검증된 중복의 보존 규칙을 사용할 때도 원본 하나는 남긴다. 선호 경로·보호 경로는 사용자가 정해야 한다. '최신'은 수정 시각 기준일 수 있으며 좋은 품질·올바른 버전을 보증하지 않는다.
4. **유사 후보는 직접 선택한다.** A와 B가 비슷하고 B와 C가 비슷하다는 이유로 A와 C까지 중복으로 취급하지 않는다. 직접 비교한 쌍의 근거를 본다.
5. **작업 미리보기 후 실행한다.** 선택 항목·원본·대상 경로를 확인한다. 분석 후 변경된 파일은 다시 분석해야 한다.

**'선택 항목을 중복으로 간주'는 검사 결과가 아니다.** 사용자가 지정한 파일을 중복으로 가정해 안전 보관하는 별도 동작이다. 다른 원본이 존재하는지 자동으로 증명하지 않으며, 선택한 파일을 모두 원래 위치에서 옮길 수 있으므로 미리보기를 확인해야 한다.

## 지원 범위와 대용량 폴더

파일 내용은 로컬에서 처리한다. 심볼릭 링크·내부 기록 폴더·권한 오류·검사 뒤 변경된 파일은 건너뛰거나 오류를 보고한다. 유사 비교에는 쌍 수·텍스트 크기·이미지 픽셀·메모리 제한이 있으며, 중단·한도·건너뛴 파일이 있으면 전체 파일을 모두 비교한 결과가 아니다. 일부 검토 미리보기도 잘릴 수 있으므로 표시된 범위를 확인한다.

같은 폴더 안의 정리·격리·되돌리기는 보호 사본을 남길 수 있다. 따라서 표시된 중복 내용 용량이 곧바로 확보 가능한 디스크 공간은 아니다. `.folder-organizer` 기록과 보관 파일을 유지해야 앱의 복원이 가능하다. 자세한 정리·복구 제한은 [README](../README.md)를 따른다.

상용 제품의 실제 기능과 이번 설계의 근거는 [비교 조사](COMPETITIVE_ANALYSIS.md)에 기록했다.
